# 长期小程序迭代路线

> 状态：本文中的八站流程和八站 marker 是 legacy 阶段描述。当前目标路线已调整为五章八互动，后续里程碑需在阶段 A 和 schema v2 迁移完成后按 [12-剧情体验与交互呈现完整计划](12-剧情体验与交互呈现完整计划.md) 重新排期。

## 阶段 P0：H5 Demo 定稿

目标：确认玩法、视觉、文案和素材方向。

交付：

- 八站流程。
- 终局规则。
- 玩法规则。
- 素材接入判断。
- 跳过规则初稿。

当前 H5 Demo 可作为玩法和视觉参考，但不是最终交付形态。

## 阶段 P1：小程序玩法原型

目标：把八个玩法拆成微信原生小程序组件。

交付：

- 玩法调试页。
- 八个玩法组件。
- 统一 `StageResult` 输出。
- 基础移动端触控适配。
- 跳过能力。

不依赖真实接口。

## 阶段 P2：线路闭环

目标：形成可独立体验的一条线路。

交付：

- 线路介绍页。
- 关卡页。
- 终局页。
- Mock 线路数据。
- 本地 storage 进度保存。
- 继续上次进度 / 重新开始。
- 历史记录列表。
- 记录详情。

## 阶段 P3：地图辅助和资源配置

目标：增强实景游览能力。

交付：

- 地图辅助页。
- 用户当前位置展示。
- 八站 marker。
- 推荐路线。
- CDN 资源 URL 配置。
- 资源加载兜底。

不做强制打卡。

## 阶段 P4：接入对方小程序

目标：从独立开发目录迁移为对方小程序业务分包。

交付：

- 分包接入。
- 登录态接入。
- 用户信息接入。
- 线路配置接口接入。
- 进度保存接口接入。
- 历史记录接口接入。
- CDN 资源接入。
- 接入验收清单。

## 阶段 P5：现有体系扩展接入

目标：连接对方已有研学平台能力。

可扩展：

- 多线路列表。
- 景点大全。
- 独立地图导览。
- 积分体系。
- 课程体系。
- AI 问答。

原则：先跳转或复用对方现有能力，避免在归途分包里重复建设平台功能。

## 阶段 P6：多线路和后台配置

目标：从单条归途线路扩展为多条研学线路。

能力：

- 多 routeId。
- 配置化站点。
- 配置化小游戏参数。
- 配置化素材 URL。
- 配置化地图点位。
- 线路上下架。
- 数据统计。

## 阶段 P7：实景验证增强

目标：如果业务需要，将地图辅助升级为到点验证。

可选能力：

- 定位打卡。
- 后端距离校验。
- 防虚拟定位。
- 打卡半径配置。
- 精度阈值配置。
- 异常频率校验。

此阶段需要重新确认隐私协议和定位权限说明。

## 长期技术原则

1. 玩法组件持续保持独立。
2. 新线路优先通过配置新增。
3. 新玩法才需要新增组件。
4. service 层隔离接口变化。
5. 不把平台能力堆进归途玩法分包。
6. 素材走 CDN，控制小程序包体。
7. 地图、定位、登录、积分尽量复用对方能力。
