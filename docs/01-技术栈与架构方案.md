# 技术栈与架构方案

> 状态：本文记录的是 legacy 八站 Demo 的初始架构，其中 `stageId`、`saveStageProgress` 和同步 storage 契约不适用于五章 schema v2。目标 beat、journey、grant、迁移和异步 Service 契约以 [12-剧情体验与交互呈现完整计划](12-剧情体验与交互呈现完整计划.md) 为准。

## 目标

把当前 `归途 · 十二兽首寻迹` H5 Demo 沉淀为可接入对方微信小程序的原生业务分包。开发阶段先保证玩法和状态闭环，接口未定时通过 mock 与 service 适配层隔离。

## 技术栈选择

### 推荐方案

```text
微信原生小程序 + TypeScript + WXML + WXSS + 原生 Component
```

推荐原因：

- 对方现有小程序技术栈未知，原生组件最容易迁移。
- 不使用 H5 WebView，符合交付前提。
- 小游戏涉及 touch、map、storage、定位等能力，原生 API 最直接。
- 分包交付边界清晰。

### 暂不推荐方案

| 方案 | 暂不推荐原因 |
|---|---|
| H5 WebView | 已明确不走 H5 WebView |
| Taro / uni-app | 除非对方项目已使用，否则会增加接入成本 |
| React/Vue 小程序框架 | 对方项目未知，迁移不确定 |
| 大型状态库 | 一期状态模型简单，增加复杂度 |
| 大型动画库 | 包体和兼容成本高 |

## 分层架构

```text
pages
  负责路由、页面级布局和业务流程

components/zodiac
  负责关卡 UI、小游戏、进度条、印记条

store
  保存当前 session、当前 stage、已获印记等运行时状态

services
  统一访问用户、线路、进度、记录等外部能力

mock
  开发期模拟线路配置、session、记录

types
  定义 route、stage、session、record、mark 等类型

utils
  storage、时间、地理距离、格式化等工具
```

## 核心架构原则

1. 玩法组件不直接请求接口。
2. 玩法组件不直接处理登录态。
3. 玩法组件不直接写入 storage。
4. 页面通过 service 保存进度。
5. 接口路径不写死在页面和组件里。
6. `routeId`、`sessionId`、`stageId` 全链路保留。
7. 支持站点 `completed` 和 `skipped` 两种结果。
8. 重新进入线路支持“继续上次进度 / 重新开始”。

## 推荐核心类型

```ts
export type StageStatus = 'locked' | 'available' | 'in_progress' | 'completed' | 'skipped';

export type MarkStatus = 'returned' | 'tracking' | 'missing';

export type ZodiacMark = {
  zodiac: string;
  label: string;
  status: MarkStatus;
};

export type TourStage = {
  stageId: string;
  order: number;
  place: string;
  title: string;
  gameType: string;
  mark: ZodiacMark;
  intro: string;
  task: string;
  location?: {
    latitude: number;
    longitude: number;
    radius?: number;
  };
  assets?: Record<string, string>;
  gameConfig?: Record<string, unknown>;
};

export type TourRoute = {
  routeId: string;
  title: string;
  subtitle?: string;
  version: string;
  stages: TourStage[];
  finalRule: {
    returned: string[];
    tracking: string[];
    missing: string[];
  };
};

export type StageProgress = {
  stageId: string;
  status: 'completed' | 'skipped';
  mark?: string | null;
  completedAt: string;
};

export type TourSession = {
  sessionId: string;
  routeId: string;
  status: 'in_progress' | 'completed' | 'abandoned';
  currentStageId: string;
  startedAt: string;
  endedAt?: string | null;
  stages: Record<string, StageProgress>;
  final: {
    completed: boolean;
    placedMarks: string[];
    completedAt?: string | null;
  };
};
```

## Service 设计

页面只调用 service，不关心底层是 mock、storage 还是真接口。

```ts
tourService.getBootstrap(routeId)
tourService.startSession(routeId, options)
tourService.getCurrentSession(routeId)
tourService.saveStageProgress(sessionId, stageId, payload)
tourService.endSession(sessionId, payload)
tourService.getRecords(routeId)
tourService.getRecordDetail(recordId)

userService.getProfile()
```

开发阶段：

```text
service -> mock JSON + wx storage
```

正式接入：

```text
service -> request wrapper -> 对方接口
```

## 分包接入建议

如果对方允许分包，建议以独立分包接入：

```json
{
  "subPackages": [
    {
      "root": "packages/zodiac",
      "pages": [
        "pages/index/index",
        "pages/stage/index",
        "pages/map/index",
        "pages/finale/index",
        "pages/records/index",
        "pages/record-detail/index"
      ]
    }
  ]
}
```

实际路径以后按对方规范调整。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 对方接口未定 | 先做 service 适配层和 mock |
| 对方技术栈未知 | 使用微信原生小程序组件 |
| 后续多线路扩展 | 全链路保留 routeId |
| 玩法被页面结构影响 | 玩法组件只输出统一结果 |
| 素材包体过大 | 优先 CDN URL，小程序包只放兜底图 |
| 定位合规不明确 | 一期定位只做地图辅助，不上传轨迹 |
