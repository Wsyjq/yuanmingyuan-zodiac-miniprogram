# I1 概念素材清单与正式替换提交规范

## 1. 用途与边界

本文登记 I1 第二版关键帧使用的五个内部概念素材，并给出可直接交给摄影、资料、设计和内容审核人员的正式素材提交要求。

当前素材只回答以下问题：

- 四屏是否能摆脱统一长方形卡片和 CSS 基础图形。
- 全幅遗址、路径、斜切对照和圆形铜盘四种构图是否属于同一产品。
- 正式图片替换后，标题、来源、事实边界和主操作是否仍有稳定位置。

当前素材不回答以下问题：

- 遗址当前状态是什么。
- 黄花阵真实路径如何连接入口与阵心。
- 大水法历史形态如何复原。
- 十二兽首当前状态如何分类。
- 任一图片是否已取得公开传播授权。

因此五个文件必须持续显示“原型素材”和“内部概念绘制”边界，不能进入 production 内容包。

## 3. 提交目录

每个正式素材使用独立目录，不通过聊天窗口散发无版本文件：

```text
submission/i1/<asset-id>/
  source/
  delivery/
  proof/
  manifest.json
  review.jpg
```

目录要求：

| 目录或文件 | 必须包含 |
|---|---|
| `source/` | 相机原片、设计源文件或机构提供的原始资料，不覆盖原文件 |
| `delivery/` | 按本文尺寸导出的 WebP、PNG、SVG 或 JSON，不带水印和社交平台 UI |
| `proof/` | 授权书、许可页面存档、来源截图、复原依据清单和审核记录 |
| `manifest.json` | 来源、权利、表示类型、AI 处理、裁切和校验和元数据 |
| `review.jpg` | 将正式候选图放入当前关键帧后的完整页面预览，不只提交裸图 |

文件名统一使用小写 ASCII、连字符和版本号，例如：

```text
ast-pro-01-hero_v001_1440x1800.webp
ast-hhz-05-path_v001_mask-1600x1200.png
```

## 4. 五个正式替换包

### 4.1 `AST-PRO-01-HERO`

| 项目 | 提交要求 |
|---|---|
| 表示类型 | `current-site-photo`，合法公共视点的现场实拍 |
| 拍摄内容 | 一处经内容负责人确认可代表序章氛围的遗址环境，不用拼接多个地点 |
| 构图 | 竖幅 4:5；建筑主体位于中下部；上部和左上保留低细节负空间；下部允许异形标题封套覆盖 |
| 原始文件 | RAW 加最高质量 JPEG，长边不低于 4000px，保留 EXIF |
| 交付文件 | `1440x1800` WebP，另交 `720x900` 弱网版本；每个文件建议不超过 900KB 和 250KB |
| 色彩 | sRGB；明场中间调可读；不得用重度 HDR、假天空或生成式建筑补全 |
| 人物与标识 | 优先无可识别游客；不可避免时需处理肖像权，不能删除或改造遗址结构 |
| 必交证明 | 拍摄者、日期、机位描述、拍摄许可或适用规则、版权授权范围 |

验收重点：页面第一眼是遗址路线而不是游戏大厅，标题覆盖后仍能辨识现场材质，但照片本身不承担未经审核的史实说明。

### 4.2 `AST-HHZ-05-PATH`

该替换 ID 是一个组合包，必须同时提交底图和审核路径层，不能只提交一张发光效果图。运行时 registry 的 `replacementId` 必须和该包 `manifest.json` 的顶层 `assetId` 相同。

| 项目 | 提交要求 |
|---|---|
| 表示类型 | `approved-site-diagram` 或经批准的现场俯视底图，加独立 `approved-route-mask` |
| 底图 | 4:3，`1600x1200` WebP；另交 `800x600` 弱网版本；不得使用未经许可的航拍或地图截图 |
| 路径层 | 同尺寸透明 PNG 或不含文字的 SVG；入口、连续路径和阵心必须是三个独立可识别语义 |
| 标记层 | 入口和阵心可交独立 SVG，但不得把“真实路径”直接烘焙进不可核验的装饰图 |
| 对齐 | 底图、路径层和标记层原点、尺寸、方向完全一致；manifest 登记北向或明确写 `orientation: display-only` |
| 动效 | 设计稿需提供完整静态终态；动效只揭示已审核路径，不重新计算路线 |
| 必交证明 | 底图来源、制作人、现场或资料审核人、路径审核日期、可公开范围 |

验收重点：先核验空间关系，再评价灯火效果。若路径依据未通过，页面只能继续显示“构图实验”，不得改成看似真实的地图。

### 4.3 `AST-DSF-05-RUIN`

| 项目 | 提交要求 |
|---|---|
| 表示类型 | `current-site-photo` |
| 构图 | 7:9 竖幅；主体在中轴附近；左右保留斜切裁切余量；不在图片内加标题 |
| 原始文件 | RAW 加最高质量 JPEG，长边不低于 4000px，保留 EXIF |
| 交付文件 | `1400x1800` WebP，另交 `700x900` 弱网版本 |
| 视角 | manifest 记录机位、朝向、焦段或等效视场；必须能和复原示意建立可解释的视角关系 |
| 处理限制 | 只允许曝光、白平衡、镜头校正和不改变结构的基础清理 |
| 必交证明 | 拍摄许可、版权授权、拍摄时间、内容审核人和现场名称 |

### 4.4 `AST-DSF-05-RECON`

| 项目 | 提交要求 |
|---|---|
| 表示类型 | `approved-reconstruction` |
| 构图 | 与 `AST-DSF-05-RUIN` 同为 7:9、同像素尺寸、同主体尺度；明确提供共同视角或视角差异说明 |
| 源文件 | 分层 PSD、TIFF、Blender 工程、CAD 导出或机构原图；文字标签不烘焙进画面 |
| 交付文件 | `1400x1800` WebP，另交 `700x900` 弱网版本 |
| 依据 | 列出每一类主要结构的资料来源、推定程度和审核人；不确定区域必须可单独标记 |
| 标签 | 页面永久显示“复原示意”；不得使用“原貌”“真实还原”等超出依据的文案 |
| AI 限制 | 生成式工具只能用于已批准结构之外的非事实纹理辅助；不得生成、补全或决定建筑结构 |
| 必交证明 | 来源清单、权利范围、复原负责人、内容审核记录、审核日期和版本 |

两张大水法图片作为一组验收。任一图片缺来源、授权或表示类型，整组保持概念占位。

### 4.5 `AST-HUG-08-DIAL`

该替换 ID 只提供铜盘视觉底座；十二个刻位的状态文字继续由获批数据渲染，不能烘焙进图片。

| 项目 | 提交要求 |
|---|---|
| 表示类型 | `decorative-interface`，不得冒充文物 |
| 构图 | 1:1 正方形，中心留空，十二条放射分区等距；外圈为状态刻位保留高对比区域 |
| 源文件 | 分层矢量源文件，图层至少拆分背景、铜盘、纹理、分隔线和中心纹样 |
| 交付文件 | `1600x1600` WebP 或无外链 SVG，另交 `800x800` 弱网版本 |
| 文字 | 底图不包含生肖名称、回归状态、年份、收藏机构或“全部归位”等结论 |
| 数据配套 | 另交 `delivery/status-set_v001.json`，资产 ID 固定为 `DATA-HUG-08-STATUS-SET`；包含状态集版本、核验日期、每项来源和可公开文案，并使用独立 manifest |
| AI 限制 | 可辅助生成纯装饰纹理，但必须登记；不得生成兽首外形、铭文或状态证据 |
| 必交证明 | 设计版权、字体与纹理授权、状态集审核单和内容负责人签字记录 |

验收重点：圆盘保持克制和可读，十二个刻位在无颜色、减少动态和弱网状态下仍能区分；空缺不能被装饰图自动填满。

## 5. Manifest 最小字段

每个 `manifest.json` 至少使用以下结构。未知值写 `null` 并阻塞审核，不写猜测值：

```json
{
  "assetId": "AST-PRO-01-HERO",
  "replacementId": "AST-PRO-01-HERO",
  "version": "v001",
  "screenIds": ["PRO-01"],
  "relatedAssetIds": [],
  "representationType": "current-site-photo",
  "sourceTitle": null,
  "sourceUri": null,
  "creator": null,
  "createdOrCapturedAt": null,
  "viewpoint": null,
  "rights": {
    "holder": null,
    "license": null,
    "territory": null,
    "channels": ["wechat-miniprogram"],
    "expiresAt": null,
    "proofFiles": []
  },
  "contentReview": {
    "reviewer": null,
    "reviewedAt": null,
    "status": "pending",
    "notes": null
  },
  "aiAssistance": {
    "used": false,
    "tool": null,
    "operations": [],
    "structureOrFactGeneration": false
  },
  "deliveries": [
    {
      "deliveryId": "AST-PRO-01-HERO:normal-base",
      "file": null,
      "role": "base",
      "representationType": "current-site-photo",
      "sourceRef": null,
      "approvalRef": null,
      "width": null,
      "height": null,
      "mimeType": null,
      "purpose": "normal",
      "sha256": null
    }
  ]
}
```

`replacementId` 必须等于顶层 `assetId`，用于和原型 registry 建立一对一替换关系。组合包中的每个 delivery 必须具有唯一 `deliveryId`，并通过 `role` 区分 `base`、`route-mask`、`entry-marker`、`center-marker`、`weak-base` 等语义；`sourceRef` 和 `approvalRef` 必须能指向 `proof/` 中的具体文件。

`contentReview.status` 只允许 `pending`、`approved`、`rejected`。正式内容包只接受 `approved`，且 `proofFiles`、交付文件和 SHA-256 校验和必须完整。`DATA-HUG-08-STATUS-SET` 不作为 `AST-HUG-08-DIAL` 的普通 delivery 混入，而是使用独立 manifest，并在两个 manifest 中通过 `relatedAssetIds` 双向关联。

## 6. 统一拒收条件

出现任一情况直接退回，不进入页面微调：

1. 社交平台水印、媒体 UI、来源不明的二次转载图。
2. 只有“网上找的”“AI 生成”等描述，没有可追溯来源和权利范围。
3. 复原图没有表示类型、复原依据、负责人和审核版本。
4. 路径、状态、年份、铭文或建筑细节由视觉设计人员自行推断。
5. 图片内烘焙正文、状态文字或无法随审核更新的事实结论。
6. 正常图和弱网图裁切不同，导致入口、阵心、对照边界或刻位语义变化。
7. 只提交裸图，没有放入四张关键帧后的页面预览。
8. 通过生成式填充改变遗址轮廓、补全建筑、移除关键现场证据或伪造共同视角。

## 7. 替换验收顺序

1. 校验目录、文件名、manifest 和 SHA-256。
2. 核验来源、授权、表示类型和内容审核状态。
3. 核验尺寸、色彩空间、正常与弱网裁切一致性。
4. 在独立原型中按 `replacementId` 替换，不修改页面事实文案来迁就图片。
5. 重跑 `verify:static`、`verify:simulator` 和 layout 检查。
6. 重新完成 375px、大屏手机、横屏、安全区、减少动态和户外强光人工评审。
7. 保留概念图和正式候选对照记录；G1 通过前不删除本登记。

## 8. 当前结论

第二版 I1 已具备可评审的构图素材，但正式素材门禁仍全部开放。当前五个 SVG 可以继续用于 development 原型和构图沟通，不能被标记为“正式候选”“已审核”或“可上线”。
