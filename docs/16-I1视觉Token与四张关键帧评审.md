# I1 视觉 Token 与四张关键帧评审

## 1. 当前状态

I1 已形成第二版可运行评审候选，但尚未标记 G1 通过。第一版因“主要画面仍由长方形和 CSS 基础图形构成、缺少可评审素材”被退回；第二版已改为素材驱动的四种非矩形构图。必须在微信开发者工具或真机查看四张关键帧、正常动态和减少动态后，才能进入 I2。

版本：`i1-g1-candidate-v2-20260719`

运行实现摘要：`10f607e52b62558fa5aa95c94c82aa659c03a644`

第二版已通过静态检查、五个本地 SVG 加载、四屏终态构图、弱网可达/不可达、陈旧素材事件、全部 storage 不变、完整 legacy simulator 和九个 legacy 布局场景回归。当前内部图只用于评价构图语言，不能作为正式遗址、路线、复原或文物素材；自动化通过也不替代 G1 人工视觉 Gate。

评审范围仅包含：

- `PRO-01` 序章主题明场。
- `HHZ-05` 黄花阵灯火结果。
- `DSF-05` 大水法遗址/复原对照。
- `HUG-08` 十二格终章暗场。
- 原型工作台、视觉 token、设备诊断和三组预览状态。

不包含其余 61 屏、正式人物、正式玩法、生产素材和 production 构建。

## 2. 视觉命题

统一视觉命题为：

```text
遗址档案不是统一白卡
→ 明场保留纸张、石材和现场光
→ 结果时局部进入铜绿、灯火或深墨暗场
→ 每次高潮结束后停在可阅读的事实终态
```

四屏需要像同一套档案系统，但不能只靠换标题区分：

| 屏幕 | 主材质 | 主构图 | 情绪 |
|---|---|---|---|
| `PRO-01` | 旧纸、全幅残垣概念图、朱砂编号 | 竖幅主视觉承载大块负空间，异形档案封套压在下部 | 安静、明确、准备出发 |
| `HHZ-05` | 深墨、有机路径概念图、黄铜结果印 | 路径由左下入口斜向右上阵心，画面边缘使用不规则裁切 | 短暂聚焦，不庆祝 |
| `DSF-05` | 灰绿遗址概念图、浅绿复原概念图、斜向资料界线 | 两层共享画布并以斜切边界对照，不模拟拖动控件 | 理性、可比较、边界清楚 |
| `HUG-08` | 深墨、黄铜、铜绿、独立待核纹理 | 圆形铜盘和十二个放射刻位 | 克制、保留空缺、逐渐安静 |

## 3. 颜色 Token

| Token | 值 | 用途 | 禁止用途 |
|---|---|---|---|
| `paper` | `#EEE5D3` | 旧纸明场、档案正文 | 不作为统一白卡铺满所有页面 |
| `ink` | `#1E2521` | 主文字、线条、工作台 | 不替代终章专用暗场层级 |
| `verdigris` | `#426A63` | 系统状态、弱网提示、资料层 | 不表达“已经回归”等事实状态 |
| `cinnabar` | `#964536` | 当前地点、来源章、单一重点 | 不用于大面积警报或庆祝 |
| `brass` | `#B08A4D` | 灯火、终章小范围重点 | 不生成金币、奖杯或通用粒子 |
| `night` | `#121815` | 重点结果和终章暗场 | 不用于日间全流程背景 |

颜色状态必须同时提供文字、纹理、边框或形状，不允许只靠颜色表达含义。

## 4. 排版 Token

| 层级 | 字体 | 当前范围 | 使用规则 |
|---|---|---|---|
| 场景标题 | `STSong` / `Songti SC` | `40–48rpx` | 每屏只出现一个主标题，最多两至三行 |
| 正文摘要 | `Songti SC` / `STSong` | `28rpx`，`1.8` 行高 | 承担发现结果与事实说明 |
| 引文 | `Songti SC` / `STSong` | `30rpx`，左侧朱砂引线 | 原文、译文和署名保持独立，不与剧情角色署名合并 |
| UI 操作 | `DIN Alternate` / `PingFang SC` | `24–26rpx` | 用于按钮、模式和短标签 |
| 档案编号 | `DIN Alternate` / monospace | `20–25rpx` | 用于 screen ID、beat、token 值和 result state |
| 辅助标签 | 同 UI 字体 | 不低于 `20rpx` | 只用于编号、图例和非关键辅助信息 |

正式上线前需要确认目标设备的宋体回退结果；当前不下载外部字体，避免原型字体请求影响弱网判断。

## 5. 间距与触控

| Token | 值 | 用途 |
|---|---|---|
| `space-1` | `8rpx` | 图标内距、微小间隔 |
| `space-2` | `16rpx` | 标签和字段内距 |
| `space-3` | `24rpx` | 控件组和卡片内距 |
| `space-4` | `32rpx` | 页面主要区块间隔 |
| `space-5` | `48rpx` | 场景标题和主体节奏 |
| 触控下限 | `44px` | 所有可操作按钮，不使用随窄屏缩小的纯 rpx 下限 |

页面应用上、下、左、右四向安全区。1024px 以下横屏保持单列，避免常见手机横屏被错误切成双栏。

## 6. 产品 Chrome

四张关键帧共同展示以下产品层，不能只评审场景插画：

| 元素 | 当前处理 | I1 边界 |
|---|---|---|
| 顶部进度 | 五段细线和地点文字 | 仅表达五地点进度，不推进主线 |
| 来源标签 | 每屏一条明确的素材/审核状态 | 当前全部为待拍摄、待审核或待登记 |

## 7. 材质 Token

| 材质 | 当前实现 | 正式替换要求 |
|---|---|---|
| 旧纸 | 低对比线性纹理和暖灰底 | 不使用污损过重、影响文字的装饰图 |
| 石材 | 内部绘制的非事实 SVG 概念图 | 替换为合法视点实拍或审核裁切 |
| 铜绿 | 低饱和状态层 | 不能直接代表公开文物状态 |
| 黄铜灯火 | 有机路径概念图和圆形阵心结果印 | 必须依据黄花阵审核底图与路径遮罩 |
| 遗址/复原 | 两个明确标签的斜切静态对照 | 两图均需来源、授权、共同视角和表示类型 |
| 十二刻位暗场 | 圆形铜盘、编号、文字、形状和待核纹理 | 必须绑定同一获批状态集和核验日期 |

所有当前画面继续显示“原型素材”，并在图内显示“内部概念绘制”来源边界。五个当前文件和正式替换提交要求见 [17-I1 概念素材清单与正式替换提交规范](17-I1概念素材清单与正式替换提交规范.md)。AI 不得决定遗址现状、复原依据、远瀛观答案、铭文和兽首状态。

## 8. 动效 Token

| Token | 值 | 使用场景 |
|---|---|---|
| `motion-enter` | `520ms` | 十二格等局部对象进入 |
| `motion-settle` | `760ms` | 标题档案板、复原示意收束 |
| `motion-result` | `1200ms` | 灯线、阵心和序章环境重点 |
| `motion-focus-delay` | `1620ms` | 黄花阵最后一段灯线完成后才聚焦阵心 |
| `ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 所有 I1 一次性进入和结果动作 |

I1 不使用循环呼吸、无限发光、庆祝粒子和持续漂浮。动画完成后必须停在可阅读终态。

减少动态版本：

| 正常动态 | 减少动态 |
|---|---|
| 标题板从下方短距离进入 | 直接显示标题板终态 |
| 路径材质一次显现，随后阵心结果印聚焦 | 直接显示完整路径和阵心结果印 |
| 复原示意短距离显现 | 直接显示双标签斜切对照 |
| 十二刻位短暂错峰落位 | 直接显示全部放射刻位终态 |

## 9. 四屏验收

### `PRO-01`

- 第一眼能识别为圆明园遗址路线，而不是游戏大厅。
- 标题、主题短句和五地点关系在首屏形成单一阅读顺序。
- 全幅残垣图持续标注为内部概念绘制，不被误认成正式现场图。
- 明场在提高屏幕亮度和户外反光模拟下仍能阅读。

### `HHZ-05`

- 当前概念图只验证入口到阵心的阅读方向；正式路径必须替换为获批底图与路径遮罩后，才能判断是否和现场空间关系一致。
- 暗场只发生在场景内部，不吞掉工作台和事实说明。
- 路径材质显现一次，随后阵心结果印聚焦；全部动作结束后停止，不自动跳转。
- 减少动态显示相同的 `path-connected` 终态。

### `DSF-05`

- “当前遗址占位”和“复原示意占位”始终同时可见。
- 对照为静态斜切双层，不伪装成尚未实现的拖动控件。
- 复原示意不覆盖或改写当前遗址标签。
- 弱网状态仍保留双重身份和文字摘要。

### `HUG-08`

- 十二个放射刻位同时使用编号、文字、形状和纹理，不只依赖颜色。
- 明确写出“状态集未审核 · 仅测试版式”。
- 不出现“全部归位”“全部收集完成”或热烈庆祝。
- 待核格保持视觉空缺，减少动态仍能理解结果。

## 10. 可访问性检查

- 原型控件使用原生 `button`，名称直接说明操作结果。
- 开发控件和产品 Chrome 都使用原生 `button`；所有按钮最小高度为 44px，焦点状态有边框和内描边。
- 查询参数错误使用 `aria-role="alert"` 和 `aria-live="assertive"`。
- 当前屏幕变化区域使用 `aria-live="polite"`。
- 颜色状态配有文字、纹理和形状。
- 点位不可达不会显示为失败。
- 减少动态不会丢失结果状态。

## 11. G1 评审清单

G1 通过前必须补齐：

1. 375px 小屏四屏截图。
2. 428–430px 大屏四屏截图。
3. 常见手机横屏和左右安全区截图。
4. 四屏正常动态与减少动态对照录制或现场确认。
5. 户外强光可读性人工检查。
6. 四屏视觉方向确认：保留、修改或退回。
7. 确认第二版已经解决第一版“矩形基础 UI、缺少素材”的退回原因。

自动截图当前会阻塞 `miniprogram-automator.screenshot()`，因此截图证据由开发者工具或真机手动保存，不以不稳定接口的成功作为 G1 条件。

G1 通过后才允许进入 I2 的 `PRO-01` 至 `PRO-07`，不得用新增页面掩盖四张关键帧的问题。
