## 三、背景与目标

### 3.1 现状
v1.3.3 已完成视觉层统一（历史铜版画扫描、旧纸背景、装订线、手写字体、边框、贴纸）。交互层经 3 份探索报告审计，发现：
- **稳定性硬伤**：1 处动画未 cancel（内存隐患）、7 页缺 onUnload 清理、4 页拖拽缺 touchcancel、1 处数据 bug
- **体验落差**：report 导出 canvas 是色块占位（与页内真图不一致）、2 处按钮是假动作、ending 视频完全占位
- **一致性缺口**：弹层/抽屉/拖拽弹回普遍无离场动画、3 处按钮 :active 不统一、涂抹页无进度反馈
- **体验提升空间**：拖拽磁吸无预提示、触觉反馈全缺、部分页答对即时反馈弱

### 3.2 本轮目标
将交互层打磨至**生产级**：无内存泄漏与卡死、无假动作、交互语汇全站统一、关键反馈时刻有触觉与节奏。

### 3.3 成功标准
1. 所有用 `anime.animate` 的页面/组件在 `onUnload`/`detached` 调用 `.cancel()`
2. 所有裸 `setTimeout` 页面有 `onUnload` 清理
3. report 保存到相册的图含历史铜版画扫描（非色块）
4. 所有 `wx:if` 弹层有离场动画（进场/离场对称）
5. 台架 19 页全 OK、无 console.error

## 四、技术规格

### 批次 1 · P0 稳定性（INT-101~104）

---

#### INT-101 · s5-timeline 动画未 cancel（最严重）

| 项 | 内容 |
|---|---|
| **优先级** | P0 |
| **问题描述** | `s5-timeline.js` 完成时创建 2 个 anime 实例（金线流动 1400ms `_goldAnim`、屏幕轻震 600ms `_shakeAnim`），但页面**无 `onUnload`**，未 `.cancel()`。用户中途返回时动画仍在向已卸载页面 `setData`，引发 warning 甚至崩溃。 |
| **根因** | 漏写生命周期清理，违反 DEV_NOTES §6.2「凡用 anime 必在 onUnload/detached cancel」约定。 |
| **影响文件** | `plate21/module/pages/s5-timeline/s5-timeline.js` |
| **参照范式** | `finale/finale.js` 的 `_cancelWipe()` + `onUnload`；`stamp-toast.js` 的 `detached` |
| **实现方案** | 1. 动画实例存为实例属性：`this._goldAnim = anime.animate(...)` / `this._shakeAnim = anime.animate(...)`<br>2. 新增 `onUnload()`：`this._goldAnim && this._goldAnim.cancel(); this._shakeAnim && this._shakeAnim.cancel()`<br>3. 同时清理该页可能存在的 `setTimeout`（若有 finish 链式延迟） |
| **验收标准** | ① 在动画播放中 nav-back 返回，台架 console 无 `setData of undefined` / `page error`；② 代码含 `onUnload` 且调用两个 `.cancel()` |
| **风险/回滚** | 低。cancel 已完成的动画无副作用；回滚即删 onUnload |

---

#### INT-102 · 7 页裸 setTimeout 缺 onUnload 清理

| 项 | 内容 |
|---|---|
| **优先级** | P0 |
| **问题描述** | 7 个页面用裸 `setTimeout`（错误闪烁 400ms、碎裂 450ms、finish 链式延迟、novelFinish 量缺口等）但无 `onUnload`。单次短延迟泄漏风险低，但多级链式 setTimeout（s3-char/s4-pattern 的 finish）在快速退出时可能在卸载后触发。 |
| **影响文件** | `s3-char.js` / `s4-pattern.js` / `s3-restore.js` / `prologue/prologue.js` / `s1-decode.js` / `s3-comic.js` / `s2-quiz.js` |
| **实现方案** | 1. 每页新增 `this._timers = []`（onLoad 初始化）<br>2. 所有 `setTimeout(fn, ms)` 改为 `this._timers.push(setTimeout(fn, ms))`<br>3. 新增 `onUnload() { this._timers.forEach(clearTimeout) }` |
| **验收标准** | ① 7 个 js 文件均含 `onUnload` 且清理 timers；② 错误反馈动画中返回，台架无 error |
| **风险/回滚** | 低 |

#### INT-103 · 4 页拖拽缺 touchcancel

| 项 | 内容 |
|---|---|
| **优先级** | P0 |
| **问题描述** | s3-restore / s3-char / s4-pattern / s5-timeline 的拖拽元素绑了 `touchstart/move/end` 但**无 `touchcancel`**。手指滑出元素、系统弹窗（来电/通知）打断时，元素卡在 dragging 态无法回弹。 |
| **影响文件** | 上述 4 页的 `.wxml`（拖拽元素节点） |
| **实现方案** | 在每个可拖拽元素的属性上加 `bindtouchcancel="onPieceEnd"`（复用 end 的落位判定逻辑；s5-timeline 为 `onCardEnd`）。touchcancel 时 dragger 的 end 会按当前坐标判定，与正常抬手一致。 |
| **验收标准** | ① 4 页 wxml 拖拽元素含 `bindtouchcancel`；② 拖拽中被系统中断后元素不卡死（真机验证） |
| **风险/回滚** | 低。touchcancel 复用 end 逻辑，行为一致 |

#### INT-201 · report 导出 canvas 画真图（最大体验落差）

| 项 | 内容 |
|---|---|
| **优先级** | P0 |
| **问题描述** | `report.js` 的 `drawReport(ctx)` 用 `#EBE1CB` 虚线色块 + 编号文字（`IMG-F04`/`IMG-F03`）模拟五层，**未绘制历史铜版画扫描 `IMG-F06.jpg`**。导出到相册的报告图与页内预览（真图）不一致，体验落差大。 |
| **根因** | canvas 2d 绘制图片需异步 `canvas.createImage()` 加载，原实现图省事用色块占位。 |
| **影响文件** | `plate21/module/pages/report/report.js`（`drawReport` + `onSave` 流程） |
| **实现方案** | 1. `drawReport` 改为异步：先同步画纸底 + 双线框 + 标题 + L1 题跋文字 + L2 边框 + L5 落款文字<br>2. 用 `const img = canvas.createImage(); img.onload = () => { ctx.drawImage(img, 90, 200, 520, 560); resolve() }; img.src = '/plate21/module/assets/img/IMG-F06.jpg'` 异步加载绘制<br>3. `onSave` 流程改为：`async`/Promise 链—— query canvas → `await drawReport(ctx)` → canvasToTempFilePath → saveImageToPhotosAlbum<br>4. 保留 `saving` 防重入；图片加载失败时 fallback 回色块（try/catch） |
| **验收标准** | ① 保存到相册的图含历史铜版画扫描（非色块）；② 台架无 error（台架 canvas 为占位，验证逻辑不崩）；③ 图片加载失败时仍能导出（fallback 色块） |
| **风险/回滚** | 中。canvas.createImage 在不同基础库行为略有差异；回滚即恢复色块 drawReport |
