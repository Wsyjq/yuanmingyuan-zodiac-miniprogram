# Word 剧情补全核对记录

日期：2026-09-25。来源：工作目录中的《第廿一图v3_副本2.docx》（原 Downloads 路径已不存在）。原稿未被修改。

## 本轮规则

依据用户澄清，仅【】中的内容作为程序标记；其外文字均保留，不再凭“像演出说明”删去原文。支持嵌套【】。题目选项通过原生按钮呈现，标题用于章节标识；答案放在完成互动或翻面后展示，不提前给出。页号和存档结构不变。

## 补全结果

- 正文范围按 Word XML 原始段落编号 129–333 核对：183 个非空原始段落，其中 165 个有应呈现文字；18 个仅为程序标记（含单独的冒号分隔符）。
- 完整文字统一进入 flow/script-content.js；flow/pages.js 只维护流程与状态，避免两套正文相互覆盖。
- 恢复被屏幕投影过滤的日记/信封提示和中心亭四段完整观察文字；观察文字不再要求先为每种构件拍照才可阅读。
- 补回黄花阵用途说明、大水法鹿角喷水和构件位置揭晓、海晏堂操作/演出文字、终局画面与信件出现段落、来信原有承接和邀请文字。
- 署名保存后先显示“档案生成”正文，再由“查看我的作品”进入报告，避免生成文字一闪而过；姓名、日期和版号使用真实状态，无服务时明确无全局版号。
- 17 张史料卡的全部正文层级与已有图注对照原稿通过。
- 按用户最新要求，文档开头的全局设定/总体规划不进入小程序，已移除“剧本创作说明”入口及运行时文本；目录重复标题不重复灌入剧情。
- 原稿非括号演出语句和“互动玩法”标题照常保留。本轮不自行润色、纠错或缩写原稿。例如雨果写信地点在原稿正文与史料表之间的表述差异仍保留，供后续单独内容审校。

## 保留的状态条件

黄花阵翻面前不显示答案，未完成题目不显示揭晓页；未到中心亭先显示到达确认。LT6 的上一位玩家引入需真实已公开记录，LT7 的“看完了吗”需实际阅读后展示。无服务时维持空状态；LT8 原稿“在经过审核之后，也许会……”是未来条件，另附真实私人保存/投稿状态。来信按原稿保留“昨天”，作为考察次日写下的信，晚到仍可阅读。

## 验证与边界

自动校验同时验证原文去向、可见屏幕投影和实际 WXML 渲染，不只匹配配置字符串。17 张史料卡独立逐段核对。完整 npm test 共 120 项通过。

微信开发者工具热重载后实际看到海晏堂补回的“观看小程序不同时辰喷水示意……”正文。工具在操作切换时出现 routeDone/webviewId 的 SDK 路由错误，后续页面可显示；不能据此宣称本轮全部原生页面已通过或真机验收。iOS/Android 仍需人工回归。

未新增或放行录音；现有音源不代表已经覆盖补回的全部句子。未逐条实听，完整旁白仍需按此版本正文进行音文核对。

Pollux 工具在本环境不可用，记录在普通文档中，未伪造其项目记录。
