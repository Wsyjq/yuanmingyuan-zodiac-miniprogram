# 资源素材与内容配置计划

> 状态：本文的 stage 级内容模型属于 legacy Demo。五章版本还要求原子 claim/source、素材授权、表现类型、不可变 content pack 和生产发布门禁，以 [12-剧情体验与交互呈现完整计划](12-剧情体验与交互呈现完整计划.md) 为准。

## 目标

把 H5 Demo 中已整理的飞书素材、裁切图和玩法配置迁移为小程序可配置资源，同时避免小程序包体过大。

## 资源存放原则

| 资源类型 | 推荐存放 | 说明 |
|---|---|---|
| 关卡主视觉 | CDN / 对象存储 | 通过接口返回 URL |
| 音频 / 视频 | CDN / 对象存储 | 不建议打进小程序包 |
| 小图标 / 兜底图 | 小程序包内 | 控制体积 |
| 玩法纹理 | CDN 优先，包内兜底 | 看体积决定 |
| Mock 图片 | 开发期本地 | 正式替换 URL |

## 一期资源策略

开发阶段：

- 可引用现有裁切素材作为 mock。
- 小程序组件先按 URL 加载。
- 缺图时使用 WXSS/SVG/纯色占位。

正式阶段：

- 图片、音频、视频由对方 CDN 或对象存储承载。
- `getBootstrap` 返回资源 URL。
- 小程序包内仅放兜底图和小图标。

## 内容配置字段

```ts
type TourStage = {
  stageId: string;
  order: number;
  place: string;
  title: string;
  intro: string;
  task: string;
  quote: string;
  gameType: string;
  mark: {
    zodiac: string;
    status: 'returned' | 'tracking' | 'missing';
  };
  assets: {
    hero?: string;
    puzzle?: string;
    reference?: string;
    audio?: string;
  };
  gameConfig: Record<string, unknown>;
};
```

## 图片规格建议

| 类型 | 建议尺寸 | 格式 |
|---|---|---|
| 关卡主视觉 | 1080x1440 或 1440x1920 | WebP/JPG |
| 拼图源图 | 900x900 或当前裁切比例 | WebP |
| 道具透明图 | 512x512 | PNG/WebP |
| 印记图标 | 512x512 | SVG/PNG/WebP |
| 兜底图 | 600x400 | WebP |

## 小程序包体控制

- 避免把所有大图放进包内。
- 首包只放必要页面和兜底资源。
- 分包内资源也应控制体积。
- 优先加载当前关卡资源。
- 后续可预加载下一关主视觉。

## 内容更新策略

一期如果没有后台管理系统，也可以通过接口返回静态 JSON 配置。

后续扩展多线路时，新增线路应尽量通过配置增加：

- routeId。
- stages。
- map markers。
- assets URLs。
- gameConfig。
- finalRule。

前端只在新增玩法类型时需要发版。
