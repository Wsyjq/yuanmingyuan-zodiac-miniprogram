# 模拟器验证

> 状态：当前脚本先验证隔离的 I0/I1 UI 原型，再回归八站 `p1` 至 `p8` legacy Demo，并断言 legacy 终局玩法后立即生成记录。该 legacy 行为与五章目标中的 beat、journey、辅助完成和显式“完成本次寻迹”收口不同。脚本不能作为 [12-剧情体验与交互呈现完整计划](12-剧情体验与交互呈现完整计划.md) 的完整验收证明。

本项目提供可重复执行的微信开发者工具模拟器验证脚本，用于覆盖首页、玩法调试页和 `归途 · 十二兽首寻迹` 八站主流程。

## 前置条件

- 已安装微信开发者工具。
- 已在开发者工具中开启：`设置 -> 安全设置 -> 服务端口`。
- 已设置环境变量 `WECHAT_DEVTOOLS_CLI`，值为本机 `cli.bat` 的绝对路径。

## 安装依赖

在仓库根目录执行：

```bash
npm install
```

依赖固定为 `miniprogram-automator@0.11.0`，这是当前开发者工具版本已验证可用的版本。

## 静态验证

```bash
npm run verify:static
```

覆盖内容：

- 所有小程序 JS 文件语法检查。
- 所有 JSON 文件解析检查。
- `app.json` 注册页面的 `.js/.wxml/.json/.wxss` 文件存在性检查。
- development 原型独立分包、禁止能力、固定 screen ID、设计 token 和事件绑定检查。
- 五个 I1 本地 SVG、来源边界、无障碍说明、正式替换 ID 和无远程依赖检查。

## 模拟器验证

```bash
npm run verify:simulator
```

脚本会自动执行：

1. 使用 CLI 打开当前仓库项目。
2. 启用自动化端口，默认 `9421`。
3. 连接真实 DevTools 模拟器运行时。
4. 验证四个 UI 原型深链、参数 allowlist 和只读产品操作。
5. 验证五个本地 SVG 完成加载、关键构图不溢出、减少动态终态和弱网/不可达替代。
6. 断言原型访问前后全部 storage 不变。
7. 验证首页加载。
8. 验证玩法调试页加载和局部玩法输出。
9. 清空 `zodiac.currentSession.*`、`zodiac.records.*` 和 `zodiac.record.*` 相关测试数据。
10. 从第 1 站跑到第 8 站。
11. 完成 legacy 终局十二格归位。
12. 检查本地游玩记录生成。

成功输出：

```text
SIMULATOR_APP_SERVICE_CHECK_PASSED
```

## 可配置项

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `WECHAT_DEVTOOLS_CLI` | 无，必须设置 | 微信开发者工具 `cli.bat` 绝对路径 |
| `WECHAT_IDE_PORT` | `9420` | 开发者工具服务端口 |
| `WECHAT_AUTO_PORT` | `9421` | 自动化 WebSocket 端口 |
| `SKIP_DEVTOOLS_BOOT` | 未设置 | 设置为 `1` 时跳过自动打开 DevTools 和启用 auto |

## 已知限制

当前开发者工具环境下，`miniprogram-automator` 的页面对象查询、真实 tap 和截图协议不稳定。因此脚本使用 app-service 运行时驱动页面方法、路由、页面内 `createSelectorQuery()` 和 storage 断言。

这仍然运行在真实 DevTools 模拟器的小程序上下文中，但只能验证加载、尺寸和状态，不替代最终的人工视觉验收。G1 截图仍需由开发者工具或真机手动保存。

脚本不会调用 `clearStorageSync` 全量清空模拟器 storage，只清理 `归途` 相关本地进度和记录 key。
