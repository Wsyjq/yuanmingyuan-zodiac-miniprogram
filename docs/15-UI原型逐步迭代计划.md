# UI 原型逐步迭代计划

## 1. 目标与边界

本文将 [14-五章逐屏体验分镜与页面、动效、素材矩阵](14-五章逐屏体验分镜与页面动效素材矩阵.md) 转换为可以逐轮实现、逐轮评审、逐轮停止或调整的执行计划。

最终目标：

```text
先验证视觉方向和页面语法
→ 再验证完整首段体验
→ 再证明人物与玩法可替换
→ 再冻结技术契约
→ 最后扩展五章并进入生产
```

固定边界：

- 五地点及顺序固定：黄花阵 → 海晏堂 → 大水法 → 远瀛观 → 雨果雕像。
- 核心主题与每个地点的知识目标固定。
- 剧情人物、载体、文案和具体玩法可以变化。
- UI 采用“明场遗址档案 + 暗场情绪高潮”。
- 第一版面向大众成人游客。
- 正式事实素材以现场实拍和可靠资料为基础，AI 只做辅助。
- 第一版不请求定位权限，不调用 GPS。

本计划按验收门槛推进，不按固定日期强行切阶段。上一轮未通过时，不把未解决问题带入下一轮。

## 2. 全程实施规则

### 2.1 隔离 legacy

- 新 UI 原型必须使用独立开发入口。
- 不替换当前八站默认路由。
- 不改写 legacy session 和记录。
- 不让原型调用 legacy 的自动跳关和全局跳过逻辑。
- 每轮完成后继续运行 legacy 静态和模拟器回归。

### 2.2 每轮只解决一类风险

| 风险 | 对应迭代 |
|---|---|
| 整体视觉是否合适 | I1 |
| 序章和首次到达是否清楚 | I2 |
| 现场如何自然进入玩法 | I3 |
| 玩法结果如何成为下一段路线 | I4 |
| 弱网、减少动态和户外使用是否可行 | I5 |
| 人物和玩法是否真的可替换 | I6 |
| 正式素材拍什么、怎么做 | I7 |
| 数据和 Service 契约是否稳定 | I8 |
| 其余章节是否可按同一规则扩展 | I9 至 I12 |
| 生产构建与旧数据迁移是否安全 | I13 |

### 2.3 每轮固定循环

```text
实现本轮最小范围
→ 375px 与大屏手机检查
→ 正常动态与减少动态检查
→ 正常网络与弱网/缺图检查
→ 真机或开发者工具评审
→ 修复本轮问题
→ 通过门槛
→ 进入下一轮
```

每轮只允许一个 `in_progress` 目标。未通过项必须留在当前轮，不用下一轮的新页面掩盖。

## 4. I0：原型隔离与基线

### 目标

建立一个可以快速评审 UI、但不会影响当前业务流程的安全试验区。

### 工作范围

1. 增加独立开发入口，例如 UI storyboard 或 prototype 页面。
2. 原型只读取独立 mock，不读取或改写 legacy 当前 session。
3. 建立屏幕选择器，可直接打开 `PRO-01`、`HHZ-05`、`DSF-05`、`HUG-08`。
4. 建立设备基线：小屏手机、大屏手机、横屏检查和安全区。
5. 所有临时图片显示“原型素材”标签。
6. 建立正常动态、减少动态、弱网和现场不可达四种预览开关。

### 交付物

- 独立原型入口。
- 原型 mock 数据。
- 四个关键屏幕空壳。
- 设备和状态切换面板。
- 原型与 production 隔离说明。

### 验收门槛

- 默认首页和八站路线没有变化。
- 清空、重置或切换原型不会修改 legacy storage。
- 原型入口可以在 development 环境访问。
- production 规划明确排除原型入口和 mock。
- `verify:static` 与 legacy 回归继续通过。

### 本轮不做

- 不实现正式 beat 引擎。
- 不迁移旧数据。
- 不接正式素材和宿主接口。

## 5. I1：视觉系统与四张高保真关键帧

### 目标

先确定视觉语言，而不是一次制作全部 65 屏。

### 工作范围

1. 建立明场和暗场颜色 token。
2. 建立标题、正文、操作、档案编号和引文排版 token。
3. 建立 4/8pt 间距、触控尺寸、安全区和层级规则。
4. 建立照片遮罩、旧纸、石材、铜板、档案和地图材质。
5. 建立按钮、顶部进度、工具包入口、地图入口和来源标签。
6. 建立点击、内容进入、纸张展开、场景变形和重点结果动效 token。
7. 完成四张关键帧：
   - `PRO-01` 序章首页。
   - `HHZ-05` 黄花阵灯火结果。
   - `DSF-05` 遗址与复原比较。
   - `HUG-08` 暗场终局板。

### 交付物

- 视觉 token 清单。
- 通用页面骨架。
- 四张高保真关键帧。
- 正常动态和减少动态对照。
- 当前参考素材可用/不可用标记。

### 验收门槛

- 明场在户外强光模拟下仍可读。
- 暗场只用于重点结果和终章，不影响日间主流程。
- 四屏看起来属于同一产品，但材质和情绪不完全相同。
- 不以统一 28rpx 白卡承载所有内容。
- 不使用卡通生肖、emoji、赛博霓虹和通用庆祝粒子。
- 每屏只有一个主要动作。

### 本轮不做

- 不制作完整人物信件。
- 不购买或批量生成正式图片。
- 不决定全部玩法细节。

## 6. I2：序章与首次到达

### 目标

验证用户是否理解这是现场路线、数字道具和手动到达体验。

### 屏幕范围

```text
PRO-01 → PRO-02 → PRO-03 → PRO-04
→ PRO-05 → PRO-06 → PRO-07
```

### 工作范围

1. 实现序章主题和数字路线包展开。
2. 使用通用剧情载体槽，不写死陈敬民。
3. 地图只开放黄花阵，其他地点保持封存。
4. 实现路线地图、开始前往、抵达后继续和到达确认。
5. 实现“点位暂不可达”入口。
6. 明确第一版不请求定位权限。
7. 保存原型内部的当前屏幕，刷新后可回到实际位置。

### 交付物

- 7 屏可点击序章流程。
- 路线包、地图、行程卡和到达确认组件。
- 现场/替代模式切换。
- 序章动效和减少动态版本。

### 验收门槛

- 用户不阅读长文也能知道下一步做什么。
- 用户能明确区分“开始前往”和“我已到达”。
- 页面不出现定位授权提示。
- 数字道具不会被误解为园区实体物件。
- 返回和刷新不会跳过到达确认。

## 7. I3：黄花阵完整章节

### 目标

验证“现场 → 观察 → 剧情槽 → 玩法 → 因果结果 → 物件”的核心页面语法。

### 屏幕范围

```text
HHZ-01 → HHZ-02 → HHZ-03 → HHZ-04
→ HHZ-05 → HHZ-06 → HHZ-07
```

### 工作范围

1. 满幅黄花阵到达主视觉。
2. 观察取景框或审核热点。
3. 可替换剧情载体组件。
4. `PLAY-HHZ-PATH` 玩法适配层。
5. 灯火沿路径抵达阵心的重点结果。
6. 数字物件揭示、确认和收入工具包。
7. 下一地点线索载体进入画面。
8. 玩法辅助、点选替代和快照恢复原型。

### 交付物

- 黄花阵 7 屏完整流程。
- 观察、剧情载体、玩法壳、结果和物件组件。
- 正常完成与查看解法两种结果。
- 灯火重点动效与静态终态。

### 验收门槛

- 用户能说出玩法来自现场的路径和阵心关系。
- 完成后不使用 Toast 或自动跳转代替结果。
- 结果动画结束后由用户主动继续。
- 物件确认前退出，恢复后不会重复发放。
- 更换剧情载体皮肤不影响观察和玩法。

## 8. I4：黄花阵至海晏堂纵向切片

### 目标

验证一个章节结果如何自然变成下一地点线索、真实路线和到达画面。

### 屏幕范围

```text
T12-01 → T12-02 → T12-03
→ T12-04 → T12-05 → T12-06 → HYT-01
```

### 工作范围

1. `PLAY-T12-DESTINATION` 可替换玩法槽。
2. 当前使用残字或地图碎片作为原型实现。
3. 结果字迹共享变形成地图终点标签。
4. 路线签进入工具包。
5. 黄花阵至海晏堂路线绘制。
6. 行程卡和手动到达。
7. 海晏堂现场主视觉展开。
8. 完成 `PRO-01` 至 `HYT-01` 的连续播放。

### 交付物

- 第一条完整纵向切片。
- 地点线索、地图共享元素转场。
- 地图、行程和到达状态恢复。
- 首段屏幕录制或逐屏截图集。

### 验收门槛

- 用户不会把可玩转场误解为实际导航。
- 实际路线接管示意效果时有明确视觉区分。
- 行走阶段没有要求持续盯屏的玩法。
- 从任一屏退出都能回到正确位置。
- 到达海晏堂后不要求重做黄花阵。

## 9. I5：纵向切片加固

### 目标

把首段从“演示可用”提升为“真实环境可测试”。

### 工作范围

1. 所有关键触控区域达到至少 44×44px 等效尺寸。
2. 拖拽玩法增加点选/按钮替代操作。
3. 增加减少动态模式。
4. 增加低清图片和文字 fallback。
5. 增加弱网、加载失败和重试状态。
6. 增加点位不可达替代观察。
7. 检查小屏、大屏、横屏和安全区。
8. 检查文字放大、长标题和长地点名。
9. 检查页面切换和动画不造成布局跳动。
10. 在低性能设备上使用简化效果。

### 交付物

- 首段异常状态矩阵。
- 可访问性检查表。
- 弱网与缺图原型。
- 正常/减少动态对照录制。
- 设备适配截图集。

### 验收门槛

- 不依赖拖拽、颜色、动画、声音或震动才能完成。
- 弱网不会出现空白主屏。
- 点位不可达不记为解题失败。
- 减少动态仍能理解全部结果。
- 按钮和文字不被安全区或键盘遮挡。

## 10. I6：可替换性压力测试

### 目标

用实际替换证明人物和玩法不会推倒页面骨架。

### 工作范围

1. 准备第二套 `NAR-ROUTE-INTRO` 和 `NAR-HHZ`。
2. 将纸质信件替换为档案卡或语音转录载体。
3. 为 `PLAY-HHZ-PATH` 准备一个不同交互方案。
4. 为 `PLAY-T12-DESTINATION` 准备一个不同交互方案。
5. 复用同一观察、结果、物件、地图和到达页面。
6. 比较两套配置的代码和数据差异。
7. 验证进行中的原型 session 固定原内容版本。

### 交付物

- `storyboard-v0` 配置。
- `storyboard-v1-test` 配置。
- 两套剧情载体。
- 两套替代玩法。
- 可替换性差异报告。

### 验收门槛

- 更换人物只修改内容和载体配置。
- 更换玩法只修改玩法引用、配置和插件内部实现。
- 结果状态仍为 `path-connected` 和 `destination-revealed`。
- 页面骨架、地图、工具包和行程逻辑不修改。
- v0 进行中 session 不混入 v1 内容。

## 11. I7：首段正式素材准备

### 目标

在页面构图已经验证后，再决定正式拍什么、画什么和生成什么。

### 工作范围

1. 输出序章、黄花阵和海晏堂的拍摄机位图。
2. 输出黄花阵观察热点和 fallback 拍摄要求。
3. 输出黄花阵至海晏堂路线实走记录模板。
4. 输出地图、数字物件、路线签和纹理的设计 brief。
5. 标记必须实拍、可设计、可 AI 辅助和禁止 AI 决定的素材。
6. 建立首段 asset manifest 草案。
7. 记录来源、授权、表示类型、digest、变换和 fallback。
8. 用正式候选素材替换原型占位图，再跑一次视觉回归。

### 交付物

- 首段拍摄 brief。
- 首段素材清单和优先级。
- asset manifest 草案。
- 首段正式候选素材包。
- 占位图替换前后对照。

### 验收门槛

- 事实画面有来源和拍摄信息。
- AI 素材不承担现场事实或答案。
- 正式图片替换后不破坏布局和交互热点。
- 低清 fallback 与主图完成同一知识目标。

## 13. I8：A2 技术契约冻结

### 进入条件

- I6 可替换性测试通过。
- [13-五章八互动阶段 A 详细矩阵](13-五章八互动阶段A详细矩阵.md) 的阶段 A 通过条件全部满足。
- 首段 UI 方向已经确认，不再频繁改变页面基本语法。

### 工作范围

1. 冻结 beat graph fixture。
2. 冻结页面类型与完成动作。
3. 冻结剧情载体、玩法插件和 `resultVisualState` 契约。
4. 冻结 interaction result 和 snapshot schema。
5. 冻结 journey、arrival receipt 和手动到达。
6. 冻结 grant effect、receipt 和确认流程。
7. 冻结 content、status 和 asset manifest。
8. 冻结 migration/completion journal。
9. 将冲突、崩溃恢复和重复回调转成测试。

### 交付物

- 可机器校验的 schema 与 fixtures。
- Service operation contract。
- 页面/玩法/素材可追溯关系。
- 并发和恢复测试矩阵。

### 验收门槛

- 每个状态写入都有前置 revision、原子效果、后继和重放结果。
- 更换内容包不会修改 Service 语义。
- 进行中 session 固定完整 `contentRef`。
- 未审核内容和素材不能进入 production artifact。

## 14. I9：海晏堂至大水法

### 屏幕范围

```text
HYT-01 → HYT-07
→ T23-01 → T23-06
→ DSF-01
```

### 本轮重点

- 十二位置观察与水力系统玩法。
- 圆盘和水线重点效果。
- 示意水线与实际路线的视觉切换。
- 第二段手动到达。
- 玩法替换仍保持 `clock-aligned` 和 `route-trace-restored`。

### 验收门槛

- 海晏堂不提前展示兽首公开状态。
- “水压”明确为示意进度。
