## 2. 状态与归属图例

内容性质、核验状态、依赖门禁和非文本表现是四个独立维度，不共用枚举。后文 beat 表按“`classification / verificationStatus / dependency`”记录；没有额外依赖时省略第三项。claim 的来源只能支持有限措辞时，在备注写“支持范围有限”，不新增 `verified-limited` 核验状态。

### 2.1 内容性质 `classification`

| 值 | 含义 |
|---|---|
| `fact` | 可独立核验的事实陈述 |
| `quotation` | 可定位原文的直接或间接引文 |
| `dramatized` | 剧情化人物、事件或文学表达 |
| `instruction` | 路线、现场观察、产品规则和操作提示 |

### 2.2 核验状态 `verificationStatus`

| 状态 | 含义 | 是否可进入 production |
|---|---|---|
| `draft` | 占位稿，尚未送审 | 不可以 |
| `needs-source` | 事实或引文缺可靠来源 | 不可以 |
| `needs-field-check` | 路线、现场对象或操作需要实地复核 | 不可以 |
| `verified` | 指定审核人已确认该原子单元可发布 | 可以，但仍须满足素材和依赖门禁 |
| `rejected` | 已否决，不得使用 | 不可以 |

### 2.3 依赖门禁

| 状态 | 含义 |
|---|---|
| `blocked` | 核验状态之外的输入尚未关闭，例如状态集、答案集、素材授权或路线版本缺失 |

`blocked` 只描述工作流依赖，不写入 `verificationStatus`。依赖解除后，内容或非文本对象仍必须单独达到 `verified`。

### 2.4 非文本表现 `representationType`

| 值 | 含义 |
|---|---|
| `documented` | 直接记录经核验的现场、文物或文献 |
| `reconstruction` | 依据来源制作的历史复原，首次展示标“复原示意” |
| `schematic` | 为解释机制或产品流程制作的示意，不宣称精确还原 |
| `dramatized` | 剧情化数字物件或视觉表达，首次展示标“数字叙事道具” |

### 2.5 叙事归属

| 归属 ID | 用途 |
|---|---|
| `system-narrator` | 到达、操作、转场、数字道具和终章系统短句 |
| `chen-jingmin` | 一封序章路线说明和五封地点数字信件；剧情化角色 |
| `lin-zhiyuan` | 固定叙事年份为 2024 的前序探索者可选手记；剧情化角色 |
| `archive` | 经过来源核验的事实、引文、图注和状态说明 |
| `current-player` | 用户自己的选择和留言，不替用户书写感受 |

### 2.6 已冻结产品规则

- 玩家始终是自己，不扮演林知远。
- 所有信件、铜板、拓印、印记和路线签均为屏幕内数字叙事道具。
- 第一版不请求定位权限，不调用 GPS。
- 实际步行阶段不设置要求持续盯屏的玩法。
- 无法到达点位时允许进入经审核的替代现场资料，不记为解题失败。
- 所有兽首公开状态仅由雨果雕像时间线 preview 读取，并在 `hugo.status-set.grant` 后持久解锁。
- 当前母本中的张德顺、实体铜板和石上刻字默认不进入 v1；数字铜板先按产品路线符号处理。
- 当前 `568` 仅是 legacy 开发占位，禁止进入新内容包。

## 4. 逐 Beat 体验矩阵
