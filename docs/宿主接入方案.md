## 1. 架构总览

「第 21 幅铜版画」是一个微信原生业务分包（WXML / WXSS / JS），交给宿主放进其小程序工程，由宿主 AppID 发布。业务页只通过 Session Store 使用 **Host Adapter（宿主适配层）**；当前仓库默认引用 Local Adapter，宿主接入时替换该实现，页面代码不改。

```
对方小程序
├─ 原有业务
├─ 公共能力
└─ plate21 业务分包
   ├─ 剧情内容 / 互动逻辑 / 状态机
   ├─ 考察记录 / 报告生成
   └─ 只调用统一接口 ↓
        Host Adapter（宿主按本契约实现）
             ↓ 转换成宿主真实能力
        宿主登录、接口、存储、媒体和统计系统
```

### 职责划分

| 模块负责 | 宿主负责 |
|---|---|
| 剧情和内容规则 | 用户登录 |
| 主线状态推进 | Token 管理 |
| 互动结果校验 | 服务器请求 |
| 四份记录与谜题级 checkpoint | API 域名配置 |
| 报告内容生成 | 用户数据归属 |
| 断点恢复规则 | 隐私协议和权限声明 |
| 模块内部错误处理 | 全局埋点和发布 |
| 内容版本管理 | 打开和退出模块 |

## 3. 接口契约

### 3.1 主接口

```ts
interface Plate21HostAdapter {
  /** 取当前用户标识。模块进入时调用（P00 封面）。
   *  失败/未登录不阻塞游玩：reject 后模块以匿名会话继续。 */
  getIdentity(): Promise<{ userId: string; accessToken?: string }>

  /** 开始或恢复一次考察会话。P00 进入时调用。
   *  无历史记录 → 宿主创建新会话返回初始快照；有 → 返回最近快照（断点恢复）。 */
  startOrResumeSession(input: StartSessionInput): Promise<SessionSnapshot>

  /** 进度落库。每个谜题完成节点调用（幂等 + 乐观锁）。
   *  失败处理：模块持久化到本地 outbox；当前交接按钮停留并允许重试。 */
  updateSession(input: SessionMutationInput): Promise<SessionMutationResult>

  /** 可选照片建议能力。当前主线不调用；未来只能提示重拍，不能阻断照片使用。
   *  未提供时 resolve {available:false, pass:false}。 */
  recognizeScene(input: RecognitionInput): Promise<RecognitionResult>

  /** 留存媒体（可选能力）。P15 保存考察报告图时调用，供宿主分享/传播。
   *  宿主不支持可 resolve null，模块仅跳过该功能。 */
  saveMedia(input: SaveMediaInput): Promise<MediaReference | null>

  /** 领取版本号（落款"第 N 版"）。P14 署名提交时调用。
   *  失败降级：模块显示"第 — 版"，不影响署名与报告生成。 */
  claimEdition(input: EditionClaimInput): Promise<EditionResult>

  /** 重新考察。清空当前会话并返回新的初始快照。 */
  resetSession(): Promise<SessionSnapshot>

  /** 埋点事件。同步、不返回；宿主可批量上报。模块保证事件枚举稳定。 */
  emitEvent(event: ModuleEvent): void
}
```

### 3.2 数据模型

```ts
/** 会话快照：模块断点恢复的唯一依据 */
interface SessionSnapshot {
  schemaVersion: 2
  sessionId: string
  revision: number            // 乐观锁版本，宿主每次落库 +1
  sessionDate: string         // 本次考察锁定日期 YYYYMMDD，跨午夜不改变
  checkpoint: Checkpoint
  stations: {                 // 四站完成状态
    s1: boolean; s2: boolean; s3: boolean; s4: boolean
  }
  puzzles: Record<string, { completedAt: number; payload?: Record<string, unknown> }>
  cards: Record<string, CardLedgerEntry>
  records: StationRecord[]    // 四份考察记录明细（见下）
  flags: Record<string, unknown> // 含 s2PhotoDraft/s2PhotoRecord/collectedReport/experienceCompletedAt
  finale: boolean             // 是否已看完反转揭示
  name?: string               // 署名（未署名为空）
  editionNo?: number          // 已领取的版本号
  updatedAt: number           // 服务器时间戳 ms
}

interface StationRecord {
  station: 's1' | 's2' | 's3' | 's4'
  recordType: 'decode' | 'rubbing' | 'restore' | 'pattern' | 'timeline' | 'zodiac' | 'pattern-pick'
  completedAt: number
  payload?: Record<string, unknown>  // 站点自定义数据（如破译答案、时间轴排列）
}

type Checkpoint =
  | 'prologue' | 's1-decode'
  | 's2-purpose' | 's2-name' | 's2-blend' | 's2-pattern'
  | 's3-hour' | 's3-zodiac' | 's3-water'
  | 's4-timeline' | 's4-password' | 'finale' | 'report'

interface CardLedgerEntry {
  cardId: string
  position: number
  digit: string
  collectedAt: number
}

interface StartSessionInput {
  scene?: string              // 宿主传入的来源场景值（可选，用于统计）
}

/** 进度变更：幂等 + 乐观锁 */
interface SessionMutationInput {
  sessionId: string
  expectedRevision: number    // 模块持有的 revision；不一致时宿主返回最新快照，模块合并重放
  operationId: string         // 幂等键（uuid）；宿主对重复 operationId 直接返回原结果
  command: SessionCommand
}

type SessionCommand =
  | { type: 'complete_station'; station: 's1'|'s2'|'s3'|'s4'; record: StationRecord; checkpoint?: Checkpoint }
  | { type: 'complete_puzzle'; puzzleId: string; completedAt: number; payload?: Record<string, unknown>; card?: CardLedgerEntry; station?: 's1'|'s2'|'s3'|'s4'; record?: StationRecord; checkpoint?: Checkpoint }
  | { type: 'collect_card'; card: CardLedgerEntry }
  | { type: 'set_checkpoint'; checkpoint: Checkpoint }
  | { type: 'set_flag'; key: string; value: unknown }
  | { type: 'complete_finale' }
  | { type: 'sign'; name: string }
  | { type: 'migrate_snapshot'; snapshot: SessionSnapshot }

interface SessionMutationResult {
  snapshot: SessionSnapshot
  applied: boolean
  conflict: boolean
}

/** 拍照校验 */
interface RecognitionInput {
  scene: 'dashuifa' | 'yuanyingguan'   // 大水法残垣 / 远瀛观石柱
  image: { filePath: string } | { base64: string }  // 宿主二选一接收
  attempt: 1 | 2
}

interface RecognitionResult {
  available?: boolean            // false 表示能力未提供，必须直接使用照片
  pass: boolean
  confidence?: number         // 0–1，可选，用于宿主调阈值
  failReason?: 'not_target' | 'too_dark' | 'blurry' | 'unknown'
}

interface SaveMediaInput {
  type: 'report' | 'photo'
  image: { filePath: string } | { base64: string }
  meta?: { name?: string; editionNo?: number; puzzle?: string; slot?: string }
}

interface MediaReference {
  mediaId: string
  url?: string
}

interface EditionClaimInput {
  sessionId: string
  name: string                // 玩家署名
}

interface EditionResult {
  editionNo: number           // 全局累计第 N 版
}

/** 埋点事件（模块保证枚举只增不改） */
type ModuleEvent =
  | { name: 'module_enter' | 'module_exit' | 'module_completed'; ts: number; checkpoint?: Checkpoint }
  | { name: 'puzzle_viewed'; puzzle: string; ts: number }
  | { name: 'puzzle_attempted'; puzzle: string; attempt: number; result: 'correct'|'incorrect'; inputMode: string; ts: number }
  | { name: 'hint_viewed'; puzzle: string; hintLevel: number; ts: number }
  | { name: 'card_collected'; cardId: string; position: number; ts: number }
  | { name: 'station_completed'; station: string; ts: number }
  | { name: 'puzzle_completed'; puzzle: string; attempts: number; ts: number }
  | { name: 'capability_fallback'; capability: string; reason: string; ts: number }
  | { name: 'photo_check'; scene: string; attempt: number; pass: boolean; ts: number }
  | { name: 'finale_viewed'; ts: number }
  | { name: 'report_saved'; ts: number }
```

### 3.3 调用时序（主线）

```
P00 进入        getIdentity → startOrResumeSession → emitEvent(module_enter)
各谜题完成      updateSession(complete_puzzle，按需原子带 card/station/checkpoint)
S2 四图拍摄     saveMedia(photo，可选) → updateSession(set_flag / complete_puzzle)
P14 署名        updateSession(sign) → claimEdition → emitEvent(finale_viewed)
P15 保存报告    saveMedia（可选）→ emitEvent(report_saved)
完成体验        updateSession(set_flag:experienceCompletedAt) → emitEvent(module_completed) → emitEvent(module_exit)
```

## 4. 开发与正式环境

```
开发期：模块 → Local Adapter → Mock 数据 + wx.Storage
接入期：模块 → Host Adapter → 宿主登录、接口和存储
```

- **两种实现必须返回完全相同的数据结构**（以 `plate21/module/contracts/adapter-api.js` 为准），模块内部不写两套流程。
- Local Adapter 行为约定：
  - `getIdentity` 返回 `{ userId: 'local-dev' }`；
  - 会话快照存 `wx.Storage`（key：`plate21_session`），`revision` 自增，`operationId` 去重；
  - `recognizeScene` 明确返回 `{ available:false, pass:false }`，不冒充模型；
  - `claimEdition` 本地计数自增；
  - `emitEvent` 打印到 console。
- 宿主的转换示例（语义参考）：

```ts
const hostAdapter: Plate21HostAdapter = {
  updateSession(input) {
    return hostRequest({
      url: '/study-tour/progress/save',
      method: 'POST',
      data: convertToHostPayload(input)
    }).then(convertToModuleSession)   // 必须转回 SessionSnapshot 结构
  },
  // ...其余方法
}
```

## 6. 宿主接入步骤（INTEGRATION.md 摘要）

1. **注册分包**：`app.json` 的 `subpackages` 加入 `plate21/module`，入口页 `pages/cover/cover`。
2. **声明权限与隐私协议**：在宿主 `app.json`（`permission` / `requiredPrivateInfos`）与《用户隐私保护指引》中声明相机、相册写权限及用途。
3. **实现 Adapter**：以 `plate21/module/adapters/local-adapter.js` 为结构模板实现 8 个方法，并让 `store/session.js` 引用宿主实现。
4. **跑验收清单**：执行 §7 的 Adapter 验收及根级 `npm test`；当前仓库没有独立 `contract-tests/` 交付目录。
5. **按需配置域名**：只有宿主 Adapter 或未来媒体实际发起网络请求时，才加入 request/downloadFile 合法域名。
6. **打开/退出模块**：`wx.navigateTo` 进入封面页；模块首页返回即 `wx.navigateBack` 回宿主，`module_exit` 事件携带完成摘要。

## 7. Adapter 验收清单

宿主 Adapter 须通过以下全部用例：

| 编号 | 用例 | 合格标准 |
|---|---|---|
| CT-01 | `getIdentity` 正常返回 | 结构含 `userId: string` |
| CT-02 | `getIdentity` 未登录 reject | 模块可匿名继续（宿主无须处理，测试模块降级） |
| CT-03 | `startOrResumeSession` 新用户 | 返回初始快照，四站全 false，revision ≥ 0 |
| CT-04 | `startOrResumeSession` 老用户 | 返回最近快照，字段完整 |
| CT-05 | `updateSession` 正常落库 | 返回快照 revision 恰好 +1，command 已生效 |
| CT-06 | `updateSession` 幂等 | 同一 `operationId` 重发 3 次，结果一致且 revision 只 +1 |
| CT-07 | `updateSession` 乐观锁 | 过期 `expectedRevision` 返回最新快照（模块合并重放） |
| CT-08 | `recognizeScene` 返回结构 | `pass: boolean`，失败时 `failReason` 在枚举内 |
| CT-09 | `recognizeScene` 超时 | ≤5s 内必须 settle（超时模块按失败处理） |
| CT-10 | `claimEdition` | 返回 `editionNo: number`，同一会话重复领取返回同号 |
| CT-11 | `saveMedia`（可选） | 返回 `MediaReference` 或 `null` |
| CT-12 | `emitEvent` | 同步不抛错；异常事件名不导致宿主崩溃 |
| CT-13 | `resetSession` | 返回新 sessionId、revision 与初始 checkpoint，并清理旧会话关联状态 |
| CT-14 | 完成态 | `set_flag:experienceCompletedAt` 幂等，`module_completed` 不重复上报 |

## 8. 边界与降级总表

| 失败场景 | 模块行为 |
|---|---|
| `getIdentity` 失败 | 匿名游玩，全流程不受影响 |
| `updateSession` 失败 | mutation 写入本地 outbox，当前交接停留并允许重试；后续写入前自动补发 |
| `recognizeScene` 不可用/失败/超时 | 当前主线不调用；未来调用时只给建议并直接允许使用照片 |
| `claimEdition` 失败 | 落款显示"第 — 版" |
| `saveMedia` 返回 null | 隐藏宿主侧分享入口，仅保留保存相册 |
| 相机权限被拒 | 提示打开设置或使用相册补录，停留当前四图页 |
| 相册权限被拒 | 仅 toast 提示，不重试 |
