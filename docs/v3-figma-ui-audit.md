## 三、必须先拍板的四个冲突

### 1. 字体（影响最大，先定）

| | 设计稿 | 现状 |
| --- | --- | --- |
| 主字体 | **Noto Serif SC**（400/500/600/700，309 段） | **LXGW WenKai 文楷**（`@font-face` + base64 注入 wxss） |
| 辅助 | Songti SC（12）、MiSans 330（10）、Noto Sans SC（6） | — |
| 杂散 | Arial / Arimo / Inter 各 1（明显漏改） | — |

现状**仓库里一个字体文件都没有**：`test/vendor-src/fonts/LXGWWenKai-Regular.ttf`（25.5 MB）
已在清理时进 `docs/v3-cleanup-manifest.json` 的 `removed`，`app.wxss` 刻意不声明全局样式。
文楷子集工具链（`pyftsubset`）随 `feat/ui-ceremonial-paper` 分支删除，见 `docs/v3-ui-review-findings.md`。

三选一，需拍板：
- **甲 换 Noto Serif SC**（贴设计稿）——中文全量 MB 级，必须 `pyftsubset` 子集化；4 个字重=4 份子集，包体压力最大
- **乙 保留文楷**（贴现状）——设计稿字号/行高/字距要重新校一遍，视觉不等于设计稿
- **丙 用系统衬线兜底**（`Songti SC` / `STSong`）——零包体成本，但 iOS/Android/开发者工具三端渲染不一致

> 另注：设计稿字阶里有 `13.57`、`8.19`、`5.44`、`6.80`、`9.999999` 这类浮点垃圾值，
> 说明画板未统一套用 Text Styles。实现前要先收敛成 8 级字阶（规范页已给出目标值）。

### 2. 色板几乎全换

现状 `walk.wxss` 是**青绿调**：`#486e65` `#627d77` `#8fc6cf` `#7b9488` `#c8cebf` `#e7e8db` …
设计稿是**暖褐纸调**：`#43362D` `#A45442` `#D8BEA0` `#EFE3CC` …
**仅 2 个色重合**（`#a45442`、`#302f2926`）。不是微调，是整套换色。

## 四、工时与风险

| 阶段 | 内容 | 量级 | 风险 |
| --- | --- | --- | --- |
| S1 | 12 色 + 8 字阶 + 4 基础规范 → CSS 变量 / WXSS 变量文件 | 小 | 字体决策未定会返工 |
| S2 | 13 个组件 → WXSS class + WXML template（禁标签/ID/属性选择器） | 中 | 印章 rot 13.8°、渐变分隔线在小程序里要改实现 |
| S3 | 6 个新版屏 → 改 `walk` 视觉层 | 中 | 只换视觉、不动 `content/story.js` 数据层 |
| S4 | 未覆盖屏补设计（八站/谜题/拍照/report） | **大** | **设计稿没有**，需另行出稿或按规范自拟 |
| S5 | 字体子集化 + 包体预算回归 | 中 | Noto Serif SC 4 字重子集仍可观，现总包 6.67 MiB |

**硬约束**（`plate21/DEV_NOTES.md`，实现时不可违反）：
- WXSS 只用 class 选择器，禁标签/ID/属性选择器
- WXSS `url()` 不能引本地图，纸纹/背景须 base64 或 `<image>`
- 字体须 `@font-face + base64` 注入 wxss（`wx.loadFontFace` 不可靠，见 `docs/v3-ui-review-findings.md` 第 2 条）
- 禁 UTF-8 BOM、禁 WXML 标签内反斜杠（`npm test` 有卫生守卫）

**素材缺口**：`18:377 彩蛋` 需要一张老师伏案写作的大插图（AI 生成），设计稿里是位图填充，
需按 `docs/` 既有合规流程产出并登记来源，不能直接从 Figma 拿图当最终素材。
