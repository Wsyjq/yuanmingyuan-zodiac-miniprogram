## 0. 摘要（一页看懂）

「第廿一图」是一个**微信原生业务分包**（WXML/WXSS/JS + 音频资产），放进宿主小程序工程、由宿主 AppID 发布。本次为**完全接入（A1 模式）**：

- **我方交付**：业务分包（21 页，含门票门页与留言簿）+ 人声音频分包 + 字体 + BGM 资产 + 本文档 + 契约与验收清单；
- **宿主实现**：工程接入（约 0.5–1 人日）+ **Host Adapter 后端对接**（门票 2 个必做方法 + 会话 4 个必做方法 + 留言簿 2 个必做方法，约 1.5–2.5 人日）+ 平台配置与提审（含微信支付商户号确认，0.5–1 人日）；
- **联调**：1–2 人日（双方），跑 CT-01~23 验收用例；
- **我方零服务器、零运维**：订单与权益、用户数据、进度、统计全部落宿主体系，义务与收益均随 AppID 归宿主。

**集成总量**：业务分包 1.47 MB（实测）+ 人声分包 13.78 MB + 主包字体（约 0.4 MB）+ BGM 32 MB（走 CDN 不进包）。
**前置确认（动手前先回答）**：①宿主小程序总包余量 ≥ 16 MB；②BGM 的 CDN 域名落点；③**微信支付商户号已绑定宿主 AppID、可售线下票务**；④发版节奏与对接人。

**产品体验一览（供非研发同事 30 秒理解）**：

```
门票门页 gate（买票/检票）
  → cover 封面 → prologue 档案交接（实体信封/信纸道具）
  → 四站实景解谜：s1 入口破译 · s2 黄花阵 · s3 海晏堂与大水法 · s4 雨果雕像
      （站间 transit 导览 + waypoint 六处可选顺路支线）
  → finale 反转揭示 → report 生成并保存「第二十一图」考察报告
  → 通关当天：report 末尾「留言簿 · 给后来的人」写一句留言
  → 次日回访：letter 次日之信 + board 留言簿读后来人的话
```

全程约 60–90 分钟；支持断点恢复（走不完次日接着走）；无需登录可匿名游玩；弱网/无声可降级走通。

## 1. 接入模式与职责划分

```
宿主小程序（宿主 AppID）
├─ 宿主原有业务
├─ 宿主公共能力（登录 / 存储 / 埋点 / 媒体库 / 支付）
└─ plate21 业务分包（我方交付，代码不再由我方修改）
   ├─ 门票门页 gate（查权益 → 购买/放行 → cover）
   ├─ 剧情内容 / 互动逻辑 / 状态机 / 报告生成
   ├─ 考察者留言簿 board（提交走宿主审核，展示只读过审内容）
   └─ 只调用统一接口 ↓
        Host Adapter（宿主按第 4 章契约实现，12 个方法）
             ↓ 转接到宿主真实能力
        宿主登录态、接口、数据库、埋点系统、支付工程、内容安全审核
```

| 我方（模块）负责 | 宿主负责 |
|---|---|
| 剧情与内容规则、主线状态推进 | 用户登录态（getIdentity） |
| 互动结果校验、四份考察记录 | 会话与进度存储（3 个接口） |
| 报告内容生成、断点恢复规则 | 门票订单与权益（支付工程、商品库、退款） |
| 留言簿前端交互与本地草稿 | 留言机检（msgSecCheck）、人工审核、留存 |
| 模块内部错误处理与降级 | Token 管理、API 域名配置 |
| 内容版本管理（每次迭代交付新版） | 用户数据归属、隐私协议与权限声明、提审发布 |

> 我方开发期自有 AppID（`wxa284707129230b80`）仅用于开发预览；**接入后模块运行在宿主 AppID 下**。
> 资金与商品口径：SKU、金额、优惠全部在宿主商品库，模块前端零金额逻辑（页面上 `¥ 19.9` 为演示占位文案，正式价格由双方确认后我方定版一行）。

### 若 A1 模式不适用：备选后端形态

A1 之外，同一套业务分包与契约可换后端形态落地（切换成本＝替换 adapter 实现，业务代码零改动）：

| 备选 | 谁做后端 | 宿主配合 | 启用周期 | 适合场景 |
|---|---|---|---|---|
| **A2 · 云函数（宿主环境）** | 我方（云函数部署到宿主的微信云开发） | 管理员开通云开发 + 授权我方人员为开发者，约 0.5 小时 | 2–4 天 | 宿主无后端人力、接受并入——**首选备选** |
| **B-并入 · 自建服务器** | 我方（自建服务器与域名） | 小程序后台加 request / downloadFile 两条合法域名 | 域名备案 2–4 周（最长杆） | 宿主连云开发也不开通、且必须要后端 |

**A2 的关键红利**（为什么它是首选备选）：

- 登录鉴权整个消失：云函数直取 OPENID，无需对接宿主登录体系；
- BGM 32 MB 放宿主云存储，**合法域名一条不用配**；
- 留言机检走云调用 `msgSecCheck`，免 access_token；
- 数据落宿主 AppID 名下，归属与导出权在宿主；云开发按量计费，小流量约 19.9 元/月起；
- 门票收款仍走宿主微信支付商户号（AppID 归宿主，此点 A1 / A2 相同）。

**B-并入的两点提醒**：①身份可信度受技术限制——宿主不交出 AppID secret，我方自建服务端无法换取可信 OPENID，统计数字的对外口径需留余地；②域名备案空窗期（2–4 周）无法外网联调，需本机开发后切换。

**过渡兜底（先上线、后补后端）**：宿主暂不做任何后端时，可用模块自带的本地适配器先行上线——进度仅存本机（换设备不恢复）、留言墙仅官方种子、门页为演示支付（点击解锁即放行，即全员免费口径）；待后端（A1 或 A2）就位后替换一行 adapter 引用即完成切换，业务零改动。

### 3.5 入口与退出

```js
// 进入（宿主首页 banner / 导览菜单 / 扫码均可）——统一指向门票门页
wx.navigateTo({ url: '/plate21/module/pages/gate/gate' })
```

- **门页即正门**：gate 先查权益——已解锁自动放行 cover；未解锁展示门票卡（购买/取消/失败/不可用四态见 §4.2）；
- **深链守卫**：旧物料或分享路径若直指 `pages/cover/cover`，cover 会自查权益，未解锁自动 `redirectTo` 回 gate——宿主无须为旧路径做任何处理；
- 退出**无需宿主代码**：模块各页返回即 `navigateBack` 回宿主页（gate 的返回按钮同为 `navigateBack`，开发版兜底逻辑不影响宿主环境）；`module_exit` 事件携带完成摘要；
- 小程序码路径建议指向 `pages/gate/gate`；
- 来源统计：`StartSessionInput.scene` 为契约预留字段；当前模块进入时未自动读取启动参数，宿主如需来源统计，可在 Adapter 层自行 `wx.getEnterOptionsSync().scene` 注入 `startOrResumeSession`。

## 4. Host Adapter 对接（宿主后端研发 · 1.5–2.5 人日）

### 4.1 方法总览（契约 v1.4.0 · 12 个方法）

| 方法 | 必做性 | 说明 |
|---|---|---|
| `getIdentity()` | **必做** | 对接宿主登录态 |
| `startOrResumeSession(input)` | **必做** | 会话创建 / 断点恢复 |
| `updateSession(input)` | **必做** | 进度落库（幂等 + 乐观锁） |
| `resetSession()` | **必做** | 重新考察 |
| `checkEntitlement(input)` | **必做（门票制）** | 权益查询（门页放行判定） |
| `requestPayment(input)` | **必做（门票制）** | 对接宿主已有付费工程 |
| `submitBoardMessage(input)` | **必做（留言簿）** | 留言提交（机检 + 人工审 + 留存） |
| `listBoardMessages(input)` | 强烈建议 | 留言展示池（不接则恒为官方种子墙） |
| `emitEvent(event)` | 强烈建议 | 17 种埋点事件（不要运营数据可先落日志表） |
| `saveMedia(input)` | 可选 | 报告图/照片存宿主媒体库；不接则 `resolve(null)` |
| `claimEdition(input)` | 可不实现 | 当前版本无页面调用（预留），不实现即落"第 — 版"降级 |
| `recognizeScene(input)` | 可不实现 | 照片识别预留能力，主线不调用 |

> 所有方法返回结构必须与 `contracts/adapter-api.js` / `adapters/local-adapter.js` 完全一致。
> **免票部署变体**：宿主若做限时免费/渠道免票，`checkEntitlement` 恒返回 `{ unlocked: true }` 即可，门页永远直通 cover，模块零改动。
> 各端点的**请求/响应 JSON 示例**与 `SessionSnapshot` **全字段表**见附录 C（后端落库/写接口可直接照抄）。

### 4.2 各方法语义与实现要求

**getIdentity() → Promise\<{ userId: string, accessToken?: string }\>**
对接宿主登录/会话接口。**未登录或失败必须 reject**——模块自动转匿名会话，全流程不受影响，宿主无须做任何兜底。

**startOrResumeSession({ scene? }) → Promise\<SessionSnapshot\>**
- 无历史会话 → 创建新会话，返回初始快照（`schemaVersion: 2`、`revision: 0`、`checkpoint: 'prologue'`、四站全 false）；
- 有历史 → 返回该用户最近快照（断点恢复）；
- `scene` 为可选来源场景值，仅作统计（透传方式见 §3.5）。

**updateSession(input) → Promise\<{ snapshot, applied, conflict }\>**——语义最严格的一个：
- **幂等**：同一 `operationId` 重复提交，返回首次结果，`revision` 不再 +1；
- **乐观锁**：`expectedRevision` 与服务端不匹配时不应用变更，返回最新快照与 `conflict: true`，模块自行合并重放；
- 正常成功：返回快照的 `revision` 恰好比请求的大 1；
- 命令共 8 种（`complete_puzzle` / `complete_station` / `collect_card` / `set_checkpoint` / `set_flag` / `complete_finale` / `sign` / `migrate_snapshot`），对落库而言都是对快照 JSON 的变更，可统一按"应用命令→存整包快照"处理；
- 接口失败无须复杂处理：模块自动把变更写入本地 outbox，之后调用前自动补发，**宿主只需保证接口可安全重试**。

**resetSession() → Promise\<SessionSnapshot\>**
清空当前会话，返回新 `sessionId`、`revision` 归零的初始快照，并清理旧会话关联状态。**注意：正式宿主必须真正创建新会话，不能只清小程序 Storage。**

**checkEntitlement({ sessionId }) → Promise\<{ unlocked: boolean, entitlementId?, unlockedAt? }\>**（门票 · 必做）
- 门页放行判定的权威来源：`unlocked: true` → 自动放行；`false` → 展示门票卡；
- **放行口径（重要）**：模块本地缓存 `flags.premiumUnlockedAt` 命中时**不调用此接口**直接放行（离线友好）；因此换设备恢复购买靠本接口（缓存天然为空），而**退款收回**只会在缓存未命中的下一次真实查询时生效——宿主如需强收回（如风控强制退票），可依赖用户换设备/清缓存，或在 `updateSession` 侧返回业务错误码由客服引导；
- 接口失败按"未解锁"处理并记 `capability_fallback` 事件——**免票部署的宿主切勿让此接口失败**，否则会把所有用户锁在门外。

**requestPayment({ sessionId, sku }) → Promise\<{ status, reason?, orderId?, entitlementId? }\>**（门票 · 必做）
- `sku` 当前固定 `'plate21_full'`（整体一张门票）；**金额与商品配置全部在宿主商品库**，模块不校验金额、前端零金额逻辑；
- 对接宿主已有付费工程的两种形态，对模块完全透明：
  - **形态 A（接口级）**：宿主 Adapter 内统单 → 拿到支付参数后 `wx.requestPayment` → 支付回调确认 → 权益落库 → 返回 `paid`；
  - **形态 B（页面级）**：Adapter 内跳宿主收银台页 → 回来后查单确认 → 返回最终状态；
- 四态语义：
  - `paid`：支付成功**且权益已落宿主库**（模块同时写本地缓存并发 `purchase_completed` 事件）；
  - `cancelled`：用户取消（模块 toast「已取消」，可再次购买）；
  - `failed`：支付失败，附可展示 `reason`（模块 toast 原文，不重试）；
  - `unavailable`：宿主未提供付费能力（如 iOS 虚拟支付受限、类目受限）——门页**隐藏购买入口**，绝不出现死按钮；
- `orderId` 供对账客服；`entitlementId` 供跨设备恢复购买。

**submitBoardMessage({ sessionId, text }) → Promise\<{ status, reason?, messageId? }\>**（留言簿 · 必做）
- 入口：通关当天 report 末尾「留言簿 · 给后来的人」入口卡；字数 1–50（模块已 trim + 截断，宿主仍须复检）；
- **UGC 硬合规通道，宿主实现必须三件事**：
  1. **机检**：调微信内容安全接口 `msgSecCheck`（含 2.0 版 user 平台昵称场景）；
  2. **人工队列**：进入宿主审核后台（先审后发或先发后审+下架，由宿主定）；
  3. **留存**：提交记录（谁/何时/原文/机检结果）留存供监管追溯与下架定位；
- 三态：`accepted`（过审入库并进展示池）/ `pending_review`（已收待人工审；先审后发模式下玩家看不到自己的话上墙）/ `rejected`（附 `reason`，模块 toast 原样提示，**不落已投递态**，玩家可改再投）；
- 宿主接口异常时模块自动降级为本地保存（`pending_review` 口径、不公开展示）并记 `capability_fallback`。

**listBoardMessages({ sessionId?, limit? }) → Promise\<{ messages: BoardMessage[] }\>**（展示池 · 强烈建议）
- `limit` 默认 6；`sessionId` 可选，宿主可据此做同会话固定排序（玩家重看留言墙不换内容）；
- **只允许返回过审内容**；每条 `{ text, from, date, source }`：
  - `from` 固定展示署名「一位考察者」——**宿主不得透出真实昵称、头像或任何可识别个人信息的字段**；
  - `source` 二值：`official_seed`（官方预置，冷启动/降级用）/ `user_generated`（真实玩家过审留言）；
  - `date` 展示日期 YYYY.MM.DD（按过审时间或考察日期给）；
- 空池/冷启动返回官方预置种子；宿主接口异常时模块自动回落本地种子池（`capabilities/board/seeds.js`，确定性取张）。

**emitEvent(event)**（同步、无返回）
事件枚举固定 17 种（只增不改）：`module_enter` / `module_exit` / `module_completed` / `puzzle_viewed` / `puzzle_attempted` / `hint_viewed` / `card_collected` / `station_completed` / `puzzle_completed` / `capability_fallback` / `photo_check` / `finale_viewed` / `report_saved` / `side_visited`（顺路支线）/ `board_message_submitted`（留言提交）/ `purchase_initiated`（发起购买）/ `purchase_completed`（支付成功）。宿主可批量上报，异常不得抛错。

**saveMedia(input)**（可选）
`{ type: 'report'|'photo', image: {filePath}|{base64}, meta }` → `Promise<{ mediaId, url? } | null>`。返回 null 时模块自动只保留"保存到相册"。

### 4.3 存储建议（最小方案）

三张表即可——`SessionSnapshot` 是**自包含 JSON**，整包落库，无需拆表：

```
plate21_session (        # 会话与进度
  user_id      主键/索引
  session_json -- SessionSnapshot 原样 JSON（含 schemaVersion=2）
  updated_at
)
plate21_order (          # 门票订单与权益（复用宿主已有订单系统亦可，满足 §4.2 语义即可）
  order_id / user_id / sku / status / entitlement_id / created_at / refunded_at
)
plate21_board (          # 留言：过审池 + 待审队列（同一张表用状态列区分）
  message_id / user_id / text / status(reviewing|accepted|rejected) / created_at / reviewed_at
)
```

接口总量：**5 个端点**（会话创建/恢复、进度写入、会话重置、权益查询、统单/支付）+ 留言两端点（提交、展示池）+ 埋点通道 + 可选媒体上传。

### 4.4 调用时序（主线）

```
gate 进入          checkEntitlement ──unlocked──→ 自动放行 cover
                      │未解锁
                      ▼ requestPayment(paid) → checkEntitlement 确认 → cover
cover 进入        getIdentity → startOrResumeSession → emitEvent(module_enter)
各谜题完成        updateSession(complete_puzzle，可原子带 card / station / checkpoint)
报告保存          saveMedia（可选）→ emitEvent(report_saved)
完成体验          updateSession(set_flag: experienceCompletedAt)
                  → emitEvent(module_completed) → emitEvent(module_exit)
通关当天·写留言   submitBoardMessage →（宿主机检+人工审）
次日回访·读留言   gate(直通) → cover(恢复) → report → board/letter → listBoardMessages
```

### 4.5 宿主实现骨架（语义参考）

```js
// host-adapter.js
const host = require('./host-request')   // 宿主自己的请求封装（带登录态）

module.exports = {
  getIdentity() {
    return host.getLoginUser()            // 未登录时此 Promise reject 即可
  },
  startOrResumeSession(input) {
    return host.post('/plate21/session/start', input).then(toSnapshot)
  },
  updateSession(input) {
    return host.post('/plate21/session/update', input).then(toMutationResult)
  },
  resetSession() {
    return host.post('/plate21/session/reset').then(toSnapshot)
  },
  checkEntitlement(input) {
    return host.post('/plate21/entitlement', input).then(toEntitlement)
  },
  requestPayment(input) {
    return host.post('/plate21/pay', input).then(toPayResult)   // 形态A；形态B见 §4.2
  },
  submitBoardMessage(input) {
    return host.post('/plate21/board/submit', input).then(toBoardResult)
  },
  listBoardMessages(input) {
    return host.post('/plate21/board/list', input).then(toBoardList)
  },
  emitEvent(event) {
    host.report(event)                    // 异步、不抛错
  },
  saveMedia() { return Promise.resolve(null) }   // 不接媒体即返回 null
}
```

关键校验点：返回值必须能通过 `contracts/adapter-api.js` 的结构（与 local-adapter 逐字段一致）。

1. 宿主把交付包 `bgm/` 目录上架到自有静态资源域名（HTTPS、已备案）；

3. 把基础 URL 告知我方定版，或宿主自行修改 `plate21/module/utils/audio-src.js` 顶部 `AUDIO_BASE` 常量（形如 `https://<宿主域名>/plate21/bgm`；文件名保持交付包原名不变）。
   > downloadFile 合法域名不要求与小程序主体一致（区别于 web-view 业务域名），任何已备案 HTTPS 域名均可。

### 5.3 音频播放的降级设计（宿主无须处理，知会即可）

- 播放组件 `audio-clip` 加载失败（onError）自动隐藏、**退回纯文稿**——弱网/无网不阻塞游玩；

- 大水法站**零配乐为设计**（现场静默秩序），不是缺资源。

## 8. 边界与降级总表

| 失败场景 | 模块行为（宿主无须处理） |
|---|---|
| getIdentity 失败/未登录 | 匿名游玩，全流程不受影响 |
| updateSession 失败 | 变更写本地 outbox，允许重试，后续调用前自动补发 |
| **checkEntitlement 失败** | 按"未解锁"处理 + `capability_fallback`（免票部署的宿主务必保证此接口可用，否则锁门） |

| **submitBoardMessage 失败** | 降级本地保存（pending 口径，不公开展示）+ `capability_fallback` |
| **listBoardMessages 失败** | 回落官方种子池（确定性取张，同一用户重看不换） |
| BGM 加载失败 | 静默跳过（氛围层，非必需） |
| 人声加载失败 | audio-clip 自动隐藏，退回纯文稿 |
| saveMedia 返回 null | 隐藏宿主侧分享入口，仅保留保存相册 |
| 相机权限被拒 | 提示打开设置或相册补录，停留当前页 |
| 相册权限被拒 | 仅 toast，不重试 |
| 定位权限被拒/失败 | 地图显示静态站点，不影响推进 |

## 附录 D：常见问题（FAQ）

**Q1：我们想做限时免费 / 内部渠道免票，怎么弄？**
`checkEntitlement` 对目标用户恒返回 `{ unlocked: true }` 即可，门页永远直通，模块零改动。免费期结束后恢复查订单。

**Q2：总包余量不足 16 MB 怎么办？**
用附录 A 的全 CDN 变体：人声也出包走 CDN，接入体积降到约 1.5 MB，代价是弱网时人声可能缺失（有退纯文稿兜底）。

**Q3：iOS 上能卖吗？**
门票是线下实景导览服务，非虚拟商品，微信支付常规可用；若宿主类目或苹果审核口径受限，`requestPayment` 返回 `unavailable`，门页自动隐藏购买入口（不出现死按钮），可配合线下购票渠道运营。

**Q4：旧二维码/分享路径还指向 cover，会出问题吗？**
不会。cover 自带深链守卫：未解锁自动跳回 gate 检票，已解锁正常进入。旧物料无须回收。

**Q5：留言审核要投入多少人力？**
单条留言上限 50 字、只有通关用户能写，量级可控。宿主自选先审后发（过审才上墙）或先发后审+下架；机检 msgSecCheck 是接口调用，无人力成本。空池有官方种子留言，不会冷场。

**Q6：我们没有后端团队 / 不想为这个项目写后端怎么办？**
本文档的 A1 模式需要宿主实现 §4 的 12 个方法；若后端人力不足，首选备选是 A2（我方写云函数部署到你们的微信云开发环境，管理员开通授权约 0.5 小时，2–4 天启用）——完整备选路线与过渡兜底见 §1「若 A1 模式不适用」。
