## 三、背景与问题

### 3.1 设计承诺
设计文档（UI-UX §5 P10/P11）设定：s3-restore 每归位一块石构件，收集对应的部首碎片（氵/亡/口/月/女/凡）；6 块全部归位后，这 6 个部首碎片传入 s3-char，作为可拖拽的拼字碎片，拼成「瀛」字。这是"考察→收集→拼合"叙事线的核心机制。

### 3.2 当前断点（v1.5.0 状态）
数据流完全断开，仅靠两边硬编码字面巧合一致掩盖：

```
s3-restore.js                    s3-char.js
─────────────                    ──────────
data.fragments: []               PIECES 常量（硬编码6部首）
  ↓ 归位成功                       onLoad() {
fragments.concat([radical])        ❌ 不读 options
  ↓ 全部归位                       ❌ 不读 session
finish() {                         └ 用本地 PIECES 初始化
  ❌ 未写 session                 }
  └ session.emit(仅埋点)
}
goChar() {
  └ wx.navigateTo(裸跳转，零参数)
}                ✘✘✘ 断点：无任何载体 ✘✘✘
```

**3 处断点**：
1. `s3-restore.js` finish()（行 178-182）：未把 fragments 写入 session
2. `s3-restore.js` goChar()（行 184-186）：跳转不带参数
3. `s3-char.js` onLoad()（行 50-65）：不读 options/session

### 3.3 本次目标
打通数据流：s3-restore 完成时把收集的部首写入 session，s3-char 初始化时从 session 读取。**不改玩法流程**（仍需全部归位才进入 s3-char），仅让数据真正连通，未来若改为部分收集可自动生效。

## 四、技术规格

### DEV-601 · s3-restore 写入 session

| 项 | 内容 |
|---|---|
| **影响文件** | `plate21/module/pages/s3-restore/s3-restore.js` |
| **位置** | finish() 方法 |
| **方案** | 在 `session.emit(...)` 后加 `session.setFlag('s3Fragments', this.data.fragments.slice())`。slice 防引用泄漏；setFlag 是异步 mutate，不阻塞跳转 |
| **验收** | ① s3-restore 完成后 `session.getSnapshot().flags.s3Fragments` 为收集的部首数组（如 `['氵','亡','口','月','女','凡']`，按归位顺序）；② 台架无 error |
| **风险/回滚** | 极低。setFlag 已被 INT-202（collectedReport）验证可用；回滚即删一行 |

---

### DEV-602 · s3-char 读取 session 初始化

| 项 | 内容 |
|---|---|
| **影响文件** | `plate21/module/pages/s3-char/s3-char.js` |
| **位置** | onLoad() 方法 |
| **方案** | 在 PIECES.map 前读取 session：`const snap = session.getSnapshot(); const collected = (snap && snap.flags && snap.flags.s3Fragments) \|\| null`。若 collected 存在，按 collected 顺序构建 pieces（当前全归位必为完整 6 个，行为不变但数据来自 session）；若 collected 为 null（异常/旧存档/直接进入），fallback 到原硬编码 PIECES 保证健壮 |
| **验收** | ① s3-char 的碎片来源是 session 读取（非独立常量）；② session 无数据时仍能正常初始化（fallback）；③ 台架无 error |
| **风险/回滚** | 低。fallback 保证健壮；回滚即恢复纯硬编码初始化 |
| **备注** | 当前 s3-restore 必须全部归位（`pieces.every(it => it.placed)`）才进入 s3-char，所以 collected 永远是完整 6 个。本次仅打通数据流，不改这个流程约束 |

---

### DEV-603 · 契约补丁（SessionSnapshot typedef 补 flags）

| 项 | 内容 |
|---|---|
| **影响文件** | `plate21/module/contracts/adapter-api.js` |
| **位置** | SessionSnapshot typedef（updatedAt 属性前） |
| **方案** | 补一行 `@property {Object<string,*>} [flags] 自定义标记位（如 s3Fragments、collectedReport）` |
| **理由** | setFlag 写入的 flags 字段当前不在契约类型里（local-adapter 实现了，但 typedef 未声明）。宿主 adapter 若严格按契约实现可能漏存。INT-202 的 collectedReport 已在用此路径，补声明让两个用例都合法 |
| **验收** | SessionSnapshot typedef 含 flags 可选属性 |
| **风险/回滚** | 极低。仅类型注释，不改运行逻辑 |
