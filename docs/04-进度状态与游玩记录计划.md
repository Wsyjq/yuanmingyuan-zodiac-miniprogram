# 进度状态与游玩记录计划

> 状态：本文记录的是 legacy `stages`、全局 skip 和旧记录结构。五章版本改用 schema v2 beat、journey、grant ledger、不可变 content version 和 completion receipt，目标契约以 [12-剧情体验与交互呈现完整计划](12-剧情体验与交互呈现完整计划.md) 为准。

## 目标

一期需要记录用户沿着 `归途 · 十二兽首寻迹` 线路进行实景解谜的进度，支持退出后恢复、换设备恢复和历史记录查看。

## 需要记录的数据

| 数据 | 一期是否记录 | 说明 |
|---|---|---|
| 当前 session | 是 | 判断是否继续上次进度 |
| 当前站点 | 是 | 恢复到退出时的关卡 |
| 已完成站点 | 是 | 用于顶部进度和历史详情 |
| 已跳过站点 | 是 | 站点支持跳过 |
| 已获得印记 | 是 | 用于印记条和终局 |
| 终局拼图状态 | 是 | 恢复终局进度 |
| 线路开始时间 | 是 | 用于记录列表 |
| 线路完成时间 | 是 | 用于记录列表 |
| 每站完成时间 | 可选 | 建议记录 |
| 小游戏具体操作过程 | 否 | 不影响恢复 |
| 小游戏失败次数 | 否 | 暂不记录 |
| 使用提示次数 | 否 | 暂不记录 |
| 演示放行状态 | 否 | 正式游客版不涉及 |
| 完整 GPS 轨迹 | 否 | 一期不做 |

## Session 状态

```ts
type SessionStatus = 'in_progress' | 'completed' | 'abandoned';
```

| 状态 | 含义 |
|---|---|
| `in_progress` | 用户正在进行中，重新进入可继续 |
| `completed` | 终局完成，生成历史记录 |
| `abandoned` | 用户选择重新开始，旧 session 被放弃 |

## Stage 状态

```ts
type StageProgressStatus = 'completed' | 'skipped';
```

| 状态 | 含义 |
|---|---|
| `completed` | 用户完成该站玩法 |
| `skipped` | 用户跳过该站环节 |

未开始站点不必写入 `stages`，可由缺省状态推导。

## 重新进入规则

用户重新进入线路介绍页时：

```text
getCurrentSession(routeId)
  -> 无进行中 session：显示开始游玩
  -> 有进行中 session：弹出继续上次进度 / 重新开始
```

### 继续上次进度

恢复：

- 当前站点。
- 已完成站点。
- 已跳过站点。
- 已获得兽首印记。
- 终局拼图状态。

### 重新开始

建议：

1. 旧 session 标记为 `abandoned`。
2. 新建 session。
3. 从第 1 站开始。
4. 不直接覆盖旧进度。

## 跳过规则

每个站点需要支持跳过，因为一期不强制用户必须到现场或必须完成每个小游戏。

建议配置：

```ts
type SkipRule = {
  givesMark: boolean;
  countsAsProgress: boolean;
};
```

默认建议：

- `countsAsProgress: true`，跳过后可以进入下一站。
- `givesMark` 待业务确认。为了完整体验可先设为 `true`，但记录状态仍为 `skipped`。

## 游玩记录定义

一条游玩记录等于用户体验一次 `归途 · 十二兽首寻迹` 线路。

### 记录列表字段

```ts
type TourRecordSummary = {
  recordId: string;
  routeId: string;
  routeTitle: string;
  status: 'completed' | 'abandoned';
  startedAt: string;
  endedAt?: string | null;
  completedStageCount: number;
  totalStageCount: number;
  markCount: number;
};
```

### 记录详情字段

```ts
type TourRecordDetail = TourRecordSummary & {
  stages: StageProgress[];
  final: {
    completed: boolean;
    placedMarks: string[];
    completedAt?: string | null;
  };
};
```

## 本地开发存储方案

开发阶段使用 `wx.setStorageSync` 和 `wx.getStorageSync`。

建议 key：

```text
zodiac.currentSession.{routeId}
zodiac.records.{routeId}
zodiac.mockUser
```

正式接入后改为后端保存，保留本地缓存作为弱网兜底可选。

## 进度保存时机

| 时机 | 操作 |
|---|---|
| 用户点击开始游玩 | `startSession` |
| 每站完成 | `saveStageProgress(completed)` |
| 每站跳过 | `saveStageProgress(skipped)` |
| 进入下一站 | 更新 `currentStageId` |
| 终局完成 | `endSession` |
| 用户重新开始 | abandon 旧 session 后 start 新 session |

## 不做的记录

- 不记录每一步点击。
- 不记录完整玩法操作过程。
- 不记录定位轨迹。
- 不记录后台持续定位。
- 不记录演示放行。
