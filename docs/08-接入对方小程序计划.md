# 接入对方小程序计划

> 状态：本文示例仍使用 legacy `stageId=p3` 深链。五章版本只允许由 Service 返回合法 resume target，并要求宿主支持幂等键、条件版本写和 completion receipt；最新接入约束以 [12-剧情体验与交互呈现完整计划](12-剧情体验与交互呈现完整计划.md) 为准。

## 目标

把 `归途 · 十二兽首寻迹` 作为微信原生小程序业务分包接入对方现有小程序。

## 需要对方提供的信息

### 项目信息

1. 小程序 AppID。
2. 技术栈：原生小程序 / Taro / uni-app / 其他。
3. 是否支持 TypeScript。
4. 基础库最低版本。
5. 分包目录规范。
6. 页面路由命名规范。
7. 代码规范、ESLint、格式化要求。

### 登录和用户

1. 统一登录方式。
2. token 存放位置。
3. 是否有统一 request 封装。
4. 是否有统一登录拦截。
5. 当前用户信息获取方式。
6. 游玩记录绑定字段：userId / 账号 ID / 手机号 / openid。

### 接口

1. 是否已有接口文档。
2. baseURL。
3. 测试环境和正式环境。
4. 鉴权方式。
5. 返回格式。
6. 错误码规范。
7. 是否签名、加密、时间戳。

### 资源

1. CDN 或对象存储规则。
2. 图片上传和访问方式。
3. 音频/视频资源承载方式。
4. 是否需要鉴权访问资源。

### 现有能力

1. 多线路列表是否已有。
2. 景点大全是否已有。
3. 地图导览是否已有。
4. 积分体系如何接入。
5. 课程体系如何接入。
6. AI 问答如何接入。

## 接入方式建议

### 方式 A：完整业务分包

我们交付：

```text
packages/zodiac/
  pages/
  components/
  services/
  mock/
  assets/
```

对方在 `app.json` 中注册分包。

优点：边界清楚，维护方便。

### 方式 B：组件 + 页面合并

对方不接受完整分包时，拆分交付：

- 玩法组件。
- 页面文件。
- service 适配说明。
- mock 数据。

缺点：接入成本更高，容易受对方目录结构影响。

## 适配层改造

开发阶段我们使用 mock service。接入时需要替换：

| 文件 | 接入内容 |
|---|---|
| `services/request.ts` | 接入对方 request 或 wx.request |
| `services/user-service.ts` | 接入对方用户信息 |
| `services/tour-service.ts` | 接入线路、进度、记录接口 |
| `mock/*` | 保留为开发兜底或测试数据 |

## 跳转协议

需要确认以下跳转：

- 从对方首页进入归途线路。
- 从多线路列表进入归途线路。
- 从景点大全进入某个站点。
- 从地图导览进入归途地图页或关卡页。
- 从归途页面跳转积分、课程、AI。

建议统一使用 routeId 和 stageId：

```text
/packages/zodiac/pages/index/index?routeId=zodiac-return
/packages/zodiac/pages/stage/index?routeId=zodiac-return&stageId=p3
```

## 接入检查清单

- 页面可从对方入口打开。
- 登录态可读取。
- 未登录时能触发对方登录流程。
- 用户信息可获取。
- 线路配置可加载。
- 进度可保存。
- 退出后可继续。
- 重新开始可创建新 session。
- 历史记录可查看。
- 地图定位权限正常。
- CDN 图片可加载。
- 分包体积符合限制。
