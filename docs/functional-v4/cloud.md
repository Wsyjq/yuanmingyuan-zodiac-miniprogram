# 私人云存档部署与边界

本轮交付云函数源码，**未部署、未发布**。默认 runtime.cloudEnv 为空，所有功能保存在本机。原数据、原报告不依赖云服务。

## 部署步骤

1. 在项目对应微信云开发环境创建集合 `plate21_private_archives`。
2. 集合安全规则使用 `archive/database.rules.json`：客户端 read/write 均 false，只允许云函数服务端 SDK 访问。
3. 云存储采用客户端不可读写规则。私人媒体由云函数上传；短期读取链接只由检查归属的云函数返回。不要将 private 前缀设置为公共读，也不要额外开放 HTTP 触发器。
4. 上传 `cloudfunctions/archive`，在云端安装 package.json 中的 SDK；配置至少 30 秒超时、合适内存，按预期访问量设置预算和告警。
5. 填入 runtime.cloudEnv，保持云函数名 archive 或同步调整 cloudFunction。先在测试环境验证下面的清单，再考虑正式发布。

客户端不传可信 userId；入口从 `cloud.getWXContext().OPENID` 确认身份，用其 SHA-256 派生每人的文档键和媒体前缀。忽略 event 中的 openid/owner。服务端没有全局纪念编号接口，不接公共留言池。

## 接口

| action | 输入 | 返回/约束 |
|---|---|---|
| load | 无身份参数 | 本人 snapshot、version；空档案 version=0 |
| save | operationId、expectedVersion、snapshot(v3) | 原子比较 version；冲突返回当前云端档案供选择；同一操作重复不新增版本 |
| media | operationId、base64 | JPEG/PNG、最大 1 MiB；服务端派生路径，内容寻址；记录本人归属 |
| urls | fileIDs（最多20） | 仅本人已登记媒体的短期链接；任何外来 fileID 整批拒绝 |

没有服务器密钥放入小程序。私密读写均通过微信云调用，不另建由客户端指定身份的 API。

## 同步语义

- 每次编辑先本地落库；同步需用户点击，不自动公开、自动发送或替换。
- 设备首次遇到非空云档案，或远端版本变化，显示冲突；“采用本机”仍带 expectedVersion，若再次变化继续提示，不强行覆盖。
- “采用云端”先下载并持久化照片，再串行替换本地会话。下载失败不替换。旧本机快照备份为 `plate21_before_cloud_replace`，可由开发人员恢复；此备份不是对外共享材料。
- 传输前将旧照片记录和私人照片的本机路径替换为服务端返回的 cloud fileID；本机原始路径不被覆盖。回复丢失的保存请求保留 operationId，下次重试先确认原操作。
- pending、已上传媒体映射与云端版本按环境分键。无网/上传失败保留本地编辑与重试信息。
- 删除私人记录后，下次同步的快照中不再包含该记录。媒体登记与历史备份尚不做自动物理清理，避免误删旧报告共用照片；正式运营如需媒体清理，应按保留策略做引用检查后删除。界面不承诺已删除所有历史副本。
- 本机照片依赖微信存储空间，用户清理小程序数据会清除本地存档；可通过纪念图导出或已启用的云存档保留。

## 测试环境验收

用两个微信账号验证互不可读，用同一账号两台设备验证冲突选择；模拟保存成功后断网重试；上传合法图/超限图/伪文件；尝试读取另一账号的 fileID；关闭客户端数据库与存储直接访问后再验证完整记录与旧报告照片。

单个快照限 512 KiB、私人记录最多 200 条、媒体登记最多 800 项，错误会保留本地数据；本轮不包含生产环境容量压测、监控平台或跨账号登录切换产品流程。

SDK 来源：[微信官方 wx-server-sdk](https://github.com/wechat-miniprogram/wx-server-sdk)。
