## 1. 整体风格设定

### 1.1 风格定位：「纸上考古」

整个小程序是一张正在被填写的**考察手册**。视觉母题取自铜版画工艺本身：密集排线（hatching）、刻痕、铜钉、朱砂印、万字纹。玩家在小程序里的每个动作（破译、拓印、归位、补全、排序），最终都"画"成了第 21 幅铜版画的一个部分——UI 必须让玩家全程感到"我在纸上记录"，而不是"我在玩手机游戏"。

三条原则：

- **纸感优先**：所有界面底色为宣纸/档案纸，不用纯白、不用玻璃拟态、不用高饱和渐变。
- **铜版画线条是唯一装饰语言**：分隔线、边框、图标全部用排线/刻痕风格；禁用圆角气泡、彩色插画图标。
- **朱砂只给"确认"**：红色全 App 只出现在印章、提交成功、关键落款处，保证"盖章=记录完成"的条件反射。

### 1.2 色彩系统

> **v1.3 旧纸档案手账改版**：参考复古手账风的「旧纸档案」路线——不是把页面做旧做暗，而是让它像一页被认真保存过的考察记录。底从 v1.2 的冷石灰白反转为**轻微泛黄的暖旧纸**，辅以低饱和浅棕、咖色、灰米、暗橄榄绿；保留铜版褐墨、铜绿、旧金、朱砂四个题材色。装饰在双框线/角花/拱券之外，新增手账六件套（§1.6）：编号标签、日期章、和纸胶带、票据锯齿、邮票齿孔、手写批注。克制原则不变：暖、轻、带灰度，不脏不压抑。仅拍照验证页保留深色夜幕底。

### 1.3 字体系统

| 层级 | 字体 | 规格 |
|---|---|---|
| 大标题 / 站名 | 思源宋体 Heavy（回退 `STSong, serif`） | 36–44rpx 字重 700，字距 +4rpx |
| 章节题跋 / 铭文引文 | 楷体（`STKaiti, KaiTi`） | 32–36rpx，配竖排或居中 |
| 正文叙事 | 系统黑体（`PingFang SC / Microsoft YaHei`） | 30rpx，行高 1.9，大留白 |
| 史料卡正文 | 系统黑体 | 26–28rpx，行高 1.8 |
| 来源标注 / 辅助说明 | 系统黑体 | 22–24rpx，墨淡 60% |
| 按钮 | 思源宋体 Medium | 30rpx，字距 +8rpx（"开 始 考 察"式疏排） |
| 手写批注（v1.3） | 可商用手写体（素材 FNT-03；回退 `STXingkai / HanziPen SC / KaiTi`） | 26rpx，行高 1.6，橄榄绿或褐墨淡 |

铭文、题跋、雨果铭文引文等"被引用文字"一律楷体 + 居中 + 上下排线分隔线，与玩家叙事（黑体）形成明确的"谁在说话"的区分。

### 1.4 组件语言

- **档案著录卡**：史料卡的载体。米白卡纸、顶部一行细排线 + 铜绿标题、底部"〔来源〕"小字、四角微磨损纹理（用一张通用磨损纹理 PNG 叠加即可）。
- **铜钉**：所有"解锁/确认/归位成功"的标记。常态为黄铜色小圆钉 + 排线高光，点亮时有 300ms 由内而外的发光扩散。
- **万字纹 / 回纹边框**：仅用于三个地方——考察手册预留页、反转揭示的铜版画边框、成果页画框。不多用，保住它在结局的仪式感。
- **印章式按钮**：主按钮为朱砂描边方印（白文"考察"二字风格化），按下时做落印动画（压下 → 抬起留印）。次按钮为墨色细线描边。
- **排线纹理**：页面顶部/底部的装饰带、分隔线，统一用 1 张可平铺的排线纹理（IMG-T01）。

### 1.5 动效语言

| 动效 | 用在哪 | 规格 |
|---|---|---|
| 墨晕染开 | 站间转场 | 墨滴从屏幕中心晕开遮盖 → 新场景从墨中显出，800–1000ms |
| 纸页翻动 | NovelView 叙事分页 | 跟手纸角 + Y 轴透视翻页，默认 680ms |
| 卡页横移 | 手册内部切页 | 横向切换，300ms |
| 排线逐笔显现 | 铜版画线条、刻痕、铭文显现 | 从左到右 clip 擦除，1200–2000ms，即刻刀声 |
| 铜钉点亮 | 归位/解锁/提交成功 | 300ms 发光 + 轻微弹性缩放 |
| 朱砂盖章 | "考察记录已保存" | 印章落下（缩放 1.3→1.0 + 3° 随机旋转）+ 一声闷响，600ms |
| 碎片碎裂 | 谜题错误反馈 | 纹样/碎片抖动后碎裂散开，400ms，无红色闪烁 |
| 卡片翻转 | 光栅卡揭示 | Y 轴 180°，500ms |

### 1.6 手账元素语言（v1.3 新增）

六件套的共同任务：让每页像「被认真归档过的一页考察手账」。全部纯 CSS 实现，素材级纹理（纸纹、胶带、手写字体）见素材清单 TEX-01～TEX-03 与 FNT-03。

| 元素 | 类名 | 用法与克制 |
|---|---|---|
| 编号标签 | `.tag-no` | 橄榄绿细框小签（如 `No.021` / `PLATE XXI`），放每页右上角「编号区」；每页至多 1 枚 |
| 日期章 | `.stamp-date` | 朱砂双圈圆章（年号/公元两行小字），旋转 -8° 盖在卡片边角；仅封面、各站完成卡、报告页使用 |
| 和纸胶带 | `.tape` / `.tape.brass` | 半透明橄榄/旧金色条，微旋转贴在主图或卡片顶边；每屏至多 2 条，不叠压正文 |
| 票据锯齿 | `.ticket-edge` | 卡片下缘撕票锯齿，用于线索票根、考察记录凭证（`.card-ticket`） |
| 邮票齿孔框 | `.perfo-frame` | 主图/铜版画外圈齿孔白边，让图像「像一枚邮票」；每屏至多 1 个主图使用 |
| 手写批注 | `.hand` / `.note-hand` | 行楷兜底（正式字体 FNT-03），图旁页边的批注小字，橄榄绿或褐墨淡；每屏至多 2 处 |

**实物拼贴增补（v1.3.1，对照复古手账参考图的差距补齐）**：

| 元素 | 类名 | 用法与克制 |
|---|---|---|
| 活页装订孔 | `.binder` | 页面左缘固定打孔列 + 竖向缝线，手账活页纸标志；叙事类页面使用，拍照页不用；使用时页面根容器 `padding-left: 52rpx` 让位 |
| 实物卡片 | `.clip-card` | 米白卡纸 + 投影 + 圆角，像贴上去的真卡纸；配 `.tilt-l` / `.tilt-r`（±1° 微旋转）制造随手贴感 |
| 撕纸边 | `.torn-divider` | 区块之间的撕纸锯齿分隔；一页至多 1 条 |
| 吊牌编号 | `.tag-no.tag-hang` | `.tag-no` 加绳孔 + 微旋转 + 投影，变档案吊牌 |
| 照片贴纸 | `.photo-sticker` | 主图白边 + 投影 + 微旋转，下方留白边可放手写说明；用于「洗出来贴上的照片」语义的主图 |
| 缝线框 | `.stitched` | 卡片内缘虚线缝边，手账常用；与双框线二选一，不叠加 |

纸底 `.paper-grain` 同步加强：暖渐变 + 细纤维 + 两三块极淡污渍斑 + 边缘晕影（透明度 ≤0.10，克制不脏）。实物感的关键仍是贴纸素材（TEX 系列），CSS 只做骨架。

归档式排版秩序：每页按「编号区（右上）→ 标题区 → 主图区 → 正文区 → 注释区 → 日期区」组织，主图要稳、标签有编号、日期要清楚、留白要保留。手账元素是点缀不是堆砌——单屏手账元素（标签/胶带/批注/章）合计不超过 4 件。

### 1.7 可商用开源参考与引入边界（2026-08-09 核验）

## 2. 内容类型 → 呈现形式映射

剧情文档自带三类标注，加上玩法与过渡，共五种内容。映射规则如下，全文严格执行：

| 剧情文档中的内容 | 呈现形式 | 组件 | 说明 |
|---|---|---|---|
| 【剧情】（正文段落、环境/音效描写、站间过渡文字） | 档案手账分页阅读 | `NovelView` | 一段一张纸，整段落墨淡入并自然换行；点按展开全文，左右滑动或页角按钮进行 3D 翻页。支持引文和剧情插图 |
| 【史料〔来源〕】 | 知识卡片弹层 | `HistoryCard` | 博物馆说明牌样式，从底部滑入，标注出处，可"收入考察手册" |
| 【行动指引】 | 任务指引条 | `TaskBanner` | 页面顶部黄铜描边横条，左侧图标（手/相机/眼睛），一句话指令。需要玩家去现实里做的事，必须用它固定呈现，不混进叙事段落 |
| 【谜题 / 玩法】 | 独立谜题页 | 各 `PuzzleView` | 一题一页，满屏交互，不打断叙事流 |
| 〔过渡：X→Y〕 | 转场页 | `TransitView` | 墨晕转场 + 路线推进图 + 该段环境叙事 |
| 过程反馈（"考察记录已保存"等） | 盖章 Toast | `StampToast` | 朱砂印章落在屏幕中下位置，600ms，不打断操作 |

**判定口诀**：玩家在"读"→ NovelView；玩家在"学"→ HistoryCard；玩家要"动手动脚"→ TaskBanner + 谜题页；玩家在"走路"→ TransitView；系统要"确认"→ StampToast。

### 3.3 进度与存档

- 五份"考察记录"对应五站完成状态；**断点恢复规则（五站状态机）由模块定义，但快照的存取一律经 Host Adapter**：进入模块时 `startOrResumeSession` 拿快照，每个谜题完成节点 `updateSession` 落库（详见《宿主接入方案.md》）。

## 4. 通用组件设计

### 4.1 NovelView 叙事阅读视图

- 布局：左侧活页装订脊，中央多层旧纸，顶部档案编号与页码，底部翻页控制和阅读进度；标题、圆形归档章、纸角和植物压纹保持克制。
- 分页：`paragraphs` 中每个正文、引文或插图项对应一张独立纸页，序章和尾声复用同一组件。
- 文字：字符按 34ms 间隔依次显墨，每个字符用 120ms 短促过渡；轻触纸面先立即展开全文，再次轻触进入下一页。
- 翻页：左滑/右滑或点击“上一页/下一页”，当前纸张默认以 680ms 透视 `rotateY` 沿书脊翻出；横纵意图锁避免与正文滚动冲突，距离/速度双阈值兼顾慢拖与快速轻扫。
- 插图位：照片以胶带、旧纸相框和手写图注呈现；引文使用楷体、引号和上下纸边形成独立证据页。
- 可用性：拖动时纸张与纸角轻微跟手；翻页阈值和落页各一次 `light` 反馈，整卷完成使用 `medium`；翻页期间锁定重复操作，`prefers-reduced-motion` 下关闭落墨淡入和长翻页动画。

### 4.2 HistoryCard 史料卡弹层

- 触发：剧情到达史料点 / 谜题解锁后自动弹出；已读过的可从考察手册回看。
- 布局：底部滑入（350ms），高度 ≤75% 屏。档案著录卡样式：铜绿标题栏（文物名 + 年代）、正文区、底部"〔来源〕…"小字、右上关闭。
- 底部主按钮："收入考察手册"（朱砂描边），点击后盖章动效 + 卡片缩入右上角手册图标。
- 已读史料卡右上角盖铜绿小圆印"已录"。

### 4.3 TaskBanner 任务指引条

- 位置：页面顶部安全区下，黄铜描边横条，高 88rpx。
- 内容：左侧动作图标（ICON 占位：取出/对比/拍照/观察/涂抹），右侧一句话指令（黑体 28rpx），例："从道具包取出《隐语对照表》与工牌拓本卡"。
- 行为：进入需要行动的阶段自动滑下；该行动完成后向上收起。
- 与叙事的边界：叙事段落里出现的"行动指引"一律提取到此组件，正文不重复。

### 4.4 StampToast 盖章反馈

- 朱砂印章（白文"已录"或"考察记录已保存"），从屏幕中上方落下，1.3→1.0 缩放 + 3° 内随机旋转，配闷响音效（AUD-S01），停留 600ms 后淡出。
- 同一时刻只允许一枚章，连续触发则合并。

### 4.5 ~~PropDrawer 道具包抽屉~~（v1.5.0 已移除）

> **v1.5.0 移除**：6 件道具（隐语对照表、工牌拓本卡、砖纹卡、薄白纸、2B 铅笔、考察手册）是**真实物理道具**，玩家手上有实物，小程序内不再虚拟显示。原 prop-drawer 抽屉组件、11 页挂载、PROP_ITEMS 常量、7 个未引用图标均已删除。需要玩家操作实物道具的环节，改由 TaskBanner / 叙事段文字引导（如 s1-decode 的"取出《隐语对照表》与工牌拓本卡，逐词比对"）。详见 `docs/v1.5.0-实体道具引导规格.md`。

### 4.6 TransitView 站间过渡

### 4.6 TransitView 站间过渡

- 三段式：① 墨晕转场遮盖；② 路线推进图（西洋楼景区简化线稿地图 IMG-M01，五站点位，已走过路径描金线推进到下一站，黄铜点标记当前位置）；③ 该站间过渡的【剧情】环境叙事（NovelView 变体）。
- 底部"继续前往"按钮。全程 ≤2 屏，可快速通过但不设跳过按钮（保护叙事节奏，每段过渡文案都很短）。

## 5. 逐页设计

> 每页含：用途 / 布局 / 交互与状态 / 对应剧情 / 素材占位。素材编号明细见《素材需求清单.md》。
> 适配器约定：凡谜题完成节点，统一 `updateSession` 落库 + `emitEvent('station_completed' / 'puzzle_completed')` 埋点；适配器调用失败一律不阻塞玩家（本地暂存、下次补发），下文只在有特殊依赖的页面单独标注。

### P00 封面 / 入口

- **用途**：模块门面，氛围建立。
- **布局**：竖向全屏。上方 1/3：排线纹理带 + 铜版画风格主视觉（IMG-C01 占位：西洋楼残柱线稿）。中部：书名「西洋楼铜版图」宋体大字，其下「第二十一图」朱砂小印。下部：主按钮"开始考察"（首次）/「继续考察 + 重新考察」（有存档时）。底部小字入口：考察手册、玩法说明。
- **交互**：进入时排线纹理从左到右显现一次（1200ms）+ 环境音（AUD-B01 风声/鸟鸣）。
- **适配器依赖**：`getIdentity`（取用户标识，失败不阻塞，可匿名游玩）→ `startOrResumeSession`（恢复进度，决定按钮显示"开始考察"还是"继续考察"）。
- **素材**：IMG-C01 主视觉、ICON-SEAL 印章、AUD-B01。

### P01 序章

- **用途**：交代背景（博物馆助理、第 21 图传闻）、发放道具包。
- **布局**：NovelView 纯叙事，约 8 段。第 2 段后插档案室插图位（IMG-P01）；民国著录卡片那段用引文卡呈现「闻有第二十一图，未见。」（IMG-P02 卡片特写图占位 + 楷体文字双保险）。
- **交互**：读到最后一段"我带上道具包……"时，屏幕底部滑出道具包开包小动画（六件道具图标依次落入抽屉），StampToast「道具包已备好」→ 按钮变为"前往西洋楼"。
- **素材**：IMG-P01、IMG-P02、六件道具图标（ICON-P1~P6）、AUD-S02 翻纸声。

### P02 第一站·铭文破译

- **用途**：谜题 1——对照实物《隐语对照表》破译实物工牌铭文，在页面输入目的地。
- **布局**：两段式（v1.5.0 改为引导查阅，工牌拓本卡与对照表不再在页面内虚拟渲染）。
  - 顶部 TaskBanner：「取出《隐语对照表》与工牌拓本卡，逐词比对」。
  - 中部：引导查阅卡（perfo-frame 档案卡样式）——标题"铭文待破译"，内含铭文原文（楷体）+ 引导文案"请取出工牌拓本卡与《隐语对照表》，逐词对勘铭文……比对对照表所列各词释义，推知铭文所指之地，填入下方"。
  - 底部：答案输入框（占位提示"铭文指向何处？"）+ "錾记为凭"朱砂提交钮。
- **交互与状态**：
  - 正确答案判定：包含"黄花阵"且包含"中心亭/基座/心墩"任一即判对（同义词表判定）。

  - 答错 1 次：输入框轻晃，提示"再逐词比对一次"。答错 2 次：提示"铭文中有几个词尚未对勘，再细看工牌与对照表"。答错 3 次：给出排除式提示（"目的地是一座迷宫"）。不锁死。
- **对应剧情**：第一段（站名 NovelView：西洋楼入口的迷茫）→ 谜题 → 成功后一段收尾叙事（"下一步的去处很明确了……"）。

- **v1.5.0 变更**：原设计把工牌拓本卡+对照表渲染成可点查的谜题 UI（点铭文热词→对照表滚动高亮），v1.5.0 改为引导查阅——玩家对着实物道具破译，页面只引导 + 收答案。

- **布局**：NovelView 短叙事（"两份东西似乎彼此咬合……会不会拼成一个什么"）→ 交互区：中央铺一张"薄白纸"，纸下覆砖纹卡（起初只见素纸）；底部一支 2B 铅笔图标。

- **反馈**：完全显现后 StampToast「考察记录已保存」→ 叙事段引出下一站疑问（"水？西洋楼最核心的水景在哪？"）→ "前往"。
- **素材**：IMG-S2C 万字纹拓印底纹（透明通道）、ICON-PENCIL、AUD-S03 铅笔沙沙声。

### P07 第三站·时辰漫画推理

- **用途**：谜题 1——十二兽首时辰报时逻辑（四格漫画推理，两小问）。
- **布局**：站名 NovelView（海晏堂废墟描写）→ HistoryCard（海晏堂·大水法营造史料：郎世宁绘图、蒋友仁水力、时辰喷水、1860 劫掠、兽首回归现状）→ 谜题区：横向四格漫画条（IMG-S3A 四格）。
- **交互与状态**：
  - 小问一：漫画前两格已给出"某时辰→某兽首喷水"的对应，第三格给出时辰（如"午时三刻将至"），问"此刻哪尊兽首喷水？"——底部 6 尊候选兽首小图单选。答对铜钉亮。
  - 小问二：第四格——所有兽首齐喷，问"此时是什么时辰？"——十二时辰滚轮/网格单选（附说明文字"每个时辰 2 小时，正午为马首"）。
  - 判定逻辑与提示：错 1 次轻晃；错 2 次在漫画格上高亮前两格的对应关系；不锁死。
- **素材**：IMG-S3A 四格漫画、6+12 兽首小图标（ICON-Z01~Z12）。

### P08 第三站·水显纸

- **用途**：使用实体水显纸找到隐藏的兽首。
- **布局**：实体道具标识、用水注意事项、三步操作指引、答案输入、分级提示和史料卡。
- **交互**：玩家在线下用少量清水湿润实体纸面；小程序不显示虚拟纸张或涂抹 Canvas，只核对纸面显出的兽首名称。
- **判定**：输入“马首”后展示回归史料卡并收集日期卡；错误时提示重新均匀显色和观察。
- **素材**：无需数字水显底图或水声；实体水显纸由物料制作流程交付。

### P09 拍照验证（通用，实例化 2 次）

- **用途**：替代"AR 扫描"——验证玩家确实在遗址现场拍对了对象，然后进入固定互动页。**不做实时 AR 叠加，不使用用户照片做底图。**
- **实例**：A. 大水法残垣（进入 P10 前置）；B. 远瀛观石柱（进入 P12 前置）。
- **流程与状态机**：
  1. **取景态**：相机全屏取景，中央叠**目标轮廓示意框**（半透明线稿：大水法残柱轮廓 / 石柱轮廓，IMG-V01/V02），TaskBanner："将残柱对准框内，保持平稳"。底部快门。
  2. **校验态**：拍摄后进入"查验中……"（排线扫描动画，1.5–2.5s）。
  3. **成功**：铜钉点亮 + StampToast「残构件已勘定」→ 自动进入对应互动页。
  4. **失败第 1 次**：温和提示"似乎没有对准遗存主体，再试一次"→ 回取景态。
  5. **失败第 2 次（兜底）**：不阻塞——提示"光线不佳也没关系，已为你调好复原图样"→ 仍进入互动页。**任何路径都不让玩家卡关。**
- **权限**：进入时申请 `scope.camera`；被拒则直接走兜底路径进互动页。
- **适配器依赖**：`recognizeScene({ scene: 'dashuifa' | 'yuanyingguan', image })`——照片校验（轮廓/颜色特征或服务端模型）由 Adapter 后的宿主能力完成，模块只发图收结果；接口超时/失败按"失败 1 次"处理，耗尽 2 次后照常兜底放行。
- **素材**：IMG-V01、IMG-V02 轮廓示意框、AUD-S05 快门声。

## 8. 架构与接入（原生业务分包 + Host Adapter）

模块采用「**原生业务分包 + Host Adapter**」两层结构：分包把完整业务带进宿主小程序，Adapter 让这套业务使用宿主的登录、接口、存储和发布体系，双方代码不直接耦合。**完整契约（接口类型定义、数据模型、交付包结构、接入步骤、契约测试）见《宿主接入方案.md》**，本节为一页摘要。

### 8.1 分层与职责

```
对方小程序
├─ 原有业务 / 公共能力
└─ plate21 业务分包（本模块：剧情内容、互动逻辑、状态机、考察记录、报告生成）
        ↓ 只调用统一接口
   Host Adapter（宿主实现，每个合作方一个）
        ↓ 转换成宿主真实能力
   宿主登录、接口、存储、媒体和统计系统
```

| 模块负责 | 宿主负责 |
|---|---|
| 剧情和内容规则 | 用户登录、Token 管理 |
| 主线状态推进、互动结果校验 | 服务器请求、API 域名配置 |
| 五份记录、报告内容生成、断点恢复规则 | 用户数据归属、隐私协议和权限声明 |
| 模块内部错误处理、内容版本管理 | 全局埋点、发布、打开和退出模块 |

### 8.2 适配器接口一览

`getIdentity` / `startOrResumeSession` / `updateSession` / `recognizeScene` / `saveMedia` / `claimEdition` / `emitEvent` —— 模块只认识这 7 个方法，不知道宿主实际调用哪个 URL、Token 放在哪里。各方法的调用方页面与降级行为见 §5 各页"适配器依赖"栏；类型定义与语义见《宿主接入方案.md》。

开发期：`模块 → Local Adapter → Mock 数据 + wx.Storage`；接入期：`模块 → Host Adapter → 宿主真实能力`。两种实现返回完全相同的数据结构，模块内部不写两套流程。

### 8.3 分包结构与宿主配合点

```
plate21/
  module/             # 完整业务模块（pages / components / assets / store）
  contracts/          # Host Adapter 类型定义
  adapters/local-adapter     # 独立开发与测试
  adapters/adapter-template  # 宿主接入模板
  manifest.json       # 权限、域名、版本声明
  INTEGRATION.md      # 接入说明
  contract-tests/     # 验证宿主 Adapter 是否合格
```

宿主侧需配合：① `app.json` 注册分包（入口 `pages/cover/cover`）；② 声明相机、相册写入权限及隐私协议用途；③ 按 adapter-template 实现 Adapter 并跑通 contract-tests。当前图片均为本地压缩衍生文件，不要求 CDN 或接口域名；增加正式视频或网络能力时再配置合法域名。

### 8.4 性能与兼容底线

- 数字拓印玩法使用 Canvas 2d 接口，单页单 canvas，涂抹层分辨率不超过屏幕 2x；水显纸为实体道具，不使用 Canvas。
- **单分包体积上限 2MB**：当前分包包含代码、贴纸与 18 个已授权 AI 压缩衍生图，实测 `1.26 MiB`；字体通过主包 base64 模块加载，主包 `0.22 MiB`、总计 `1.48 MiB`。正式视频若恢复则走已登记网络地址，不打入分包。
- 最低基础库 2.30.0；iOS/Android 双端真机验收（重点：相机取景比例、拓印 Canvas 性能、实体道具输入和字体渲染）。
